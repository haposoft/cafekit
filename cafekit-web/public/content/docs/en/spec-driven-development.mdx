## The simple version

The spec is the durable contract, not chat memory. New work stores that contract in `specs/<feature>/plan.md` and flat `task-NN-*.md` files.

<SddLoopVisual locale="en" />

## What each artifact answers

<SddArtifactMap locale="en" />

| Artifact | Question |
|---|---|
| `plan.md` | What outcome, scope, exclusions, acceptance, decisions, and task map were approved? |
| `task-NN-*.md` | What single outcome is executable now, who owns it, and what exact proof is required? |
| Final inline `## Receipt` | What current command and output prove the task passed? |

## Working rule

1. Use brainstorm only while intent or architecture is unresolved.
2. Specs opens C1, writes the plan and tasks, then presents C2 findings.
3. Planning stops. Start work only with a new explicit develop invocation.
4. Develop executes one unblocked task; test and code review verify it.
5. Sync only observed Status and proof. The user decides completion at C3.

<SddCompareVisual locale="en" />

Use the full path for substantial, risk-elevated, multi-file, runtime, data, auth, package, or handoff-sensitive work. Clear isolated one- or two-file routine changes may use direct work.
