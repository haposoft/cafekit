## Lifecycle

```text
request
  -> C1: confirm outcome, scope, exclusions, constraints
  -> plan.md + flat task-NN-*.md files
  -> adversarial review
  -> C2: accept, revise, or KEEP named findings
  -> stop planning
  -> new explicit /cf:develop invocation
  -> exact verification + final inline Receipt
  -> C3: user decides whether proof and limitations are sufficient
```

Planning never starts implementation. No command, hook, reviewer, or host state may invent C1, C2, C3, or execution proof.

## Artifact contract

```text
specs/<feature>/
├── plan.md
├── task-01-<slug>.md
└── task-NN-<slug>.md
```

`plan.md` records the C1 decision, acceptance criteria, exclusions, findings decisions, dependencies, and task map. Each flat task owns one outcome and exactly one `Status:` field.

Every task should state:

- outcome and explicit boundaries
- owned files or surfaces
- dependencies and blockers
- acceptance criteria mapped to the plan
- exact planned verification command
- final inline `## Receipt`

## Human decisions

| Gate | Question | Effect |
|---|---|---|
| C1 | What exactly are we planning? | Locks outcome, scope, exclusions, constraints, and unresolved choices. |
| C2 | What material gaps or risks remain? | The user accepts, requests revision, or keeps a named limitation. |
| C3 | Is the current result good enough to close? | The user evaluates current receipts and unresolved limitations. |

## Execution and proof

`/cf:develop <feature>` selects one unblocked task, scouts the real integration path, implements only that boundary, and runs the task's exact proof command. The controller is the sole writer of task state and proof.

A done task requires a current final inline Receipt containing:

- exact command
- `Exit: 0`
- `Verification: PASS`
- runtime-derived `Base` and `Head`
- non-empty fenced current output

`NO_TESTS`, zero executed tests, stale output, or a green command unrelated to acceptance does not pass.

## Sync boundary

`/cf:sync` performs surgical updates to observed task Status and inline Receipts. It does not invent execution, approval, readiness, or completion.
