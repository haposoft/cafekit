Main delivery path は [Core workflow](/ja/docs/core-workflow) で詳しく説明しています。このページは標準 feature path 以外の command selector として使います。

## Core feature workflow

| Command | Use when |
|---|---|
| `/cf:specs` | C1 scope、reviewed plan、flat executable tasks、C2 decision が必要。 |
| `/cf:develop` | spec または task file が approved で implementation ready。 |
| `/cf:test` | commands、build、tests、UI checks、runtime reachability の evidence が必要。 |
| `/cf:code-review` | bugs、security、drift、missing proof の adversarial review。 |
| `/cf:sync` | Observed task Status または final inline Receipt を proof の捏造なしで sync。 |

Idea が曖昧、architecture が未決定、scope を pressure-test したい場合だけ、この path の前に `/cf:brainstorm` を使います。

## Bug and incident

| Command | Use when |
|---|---|
| `/cf:debug` | root cause が不明。code change 前に evidence を作る diagnostic-first workflow。 |
| `/cf:fix` | diagnosis 後に小さく安全に bug を修正し regression checks を行う。 |

## Docs and artifacts

| Command | Use when |
|---|---|
| `/cf:docs --init` | project docs がない。 |
| `/cf:docs --update` | source changes が docs refresh を必要とする。 |
| `/cf:docs --reconstruct <scope>` | existing system の source-backed as-is docs が必要。 |

## Release

| Command | Use when |
|---|---|
| `/cf:git commit` | verified changes を focused conventional commit にする。 |
| `/cf:git push` | tests と review が clean で branch を publish できる。 |

Codex CLI は同じ public workflow を native `$cf-*` skills で提供します。
