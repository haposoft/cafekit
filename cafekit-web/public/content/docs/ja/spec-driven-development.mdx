## Simple version

Spec は chat memory ではなく durable contract です。New work は `specs/<feature>/plan.md` と flat `task-NN-*.md` に保存します。

<SddLoopVisual locale="ja" />

## Artifact questions

<SddArtifactMap locale="ja" />

| Artifact | Question |
|---|---|
| `plan.md` | Approved outcome、scope、exclusions、acceptance、decisions、task map は何か? |
| `task-NN-*.md` | 今 executable な one outcome、owner、required exact proof は何か? |
| Final inline `## Receipt` | Task pass を証明する current command と output は何か? |

## Working rule

1. Intent または architecture が未解決な間だけ brainstorm。
2. Specs は C1 を開き、plan/tasks を作り、C2 findings を提示。
3. Planning stop。New explicit develop invocation だけが work を開始。
4. Develop は one unblocked task を実行し、test と code review が verify。
5. Observed Status/proof だけを sync。C3 で user が completion を決定。

<SddCompareVisual locale="ja" />

Substantial、risk-elevated、multi-file、runtime、data、auth、package、handoff-sensitive work では full path を使います。Clear isolated one/two-file routine change は direct work が可能です。

[Core workflow](/ja/docs/core-workflow) と [Spec lifecycle](/ja/docs/spec-lifecycle) を参照してください。
