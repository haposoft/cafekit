## Lifecycle

```text
request
  -> C1: outcome、scope、exclusions、constraints を確認
  -> plan.md + flat task-NN-*.md
  -> adversarial review
  -> C2: accept、revise、または named finding を KEEP
  -> planning stop
  -> 新しい explicit /cf:develop invocation
  -> exact verification + final inline Receipt
  -> C3: proof と limitations が十分か user が決定
```

Planning は implementation を開始しません。Command、hook、reviewer、host state は C1/C2/C3 や execution proof を捏造できません。

## Artifact contract

```text
specs/<feature>/
├── plan.md
├── task-01-<slug>.md
└── task-NN-<slug>.md
```

`plan.md` は C1 decision、acceptance criteria、exclusions、findings decisions、dependencies、task map を保持します。各 flat task は one outcome と exactly one `Status:` を持ちます。

Task に必要な内容:

- outcome と explicit boundaries
- owned files または surfaces
- dependencies と blockers
- plan に map された acceptance criteria
- exact planned verification command
- final inline `## Receipt`

## Human decisions

| Gate | Question | Effect |
|---|---|---|
| C1 | 何を planning するか? | Outcome、scope、exclusions、constraints、未解決 choices を lock。 |
| C2 | Material gaps または risks は何か? | User が accept、revision request、または named limitation を KEEP。 |
| C3 | Current result は close に十分か? | User が current receipts と unresolved limitations を評価。 |

## Execution and proof

`/cf:develop <feature>` は one unblocked task を選び、real integration path を scout、task boundary だけを実装し、exact proof command を実行します。Controller だけが task state と proof を書きます。

Done task は exact command、`Exit: 0`、`Verification: PASS`、runtime-derived `Base`/`Head`、non-empty fenced current output を持つ current final inline Receipt が必要です。

`NO_TESTS`、zero executed tests、stale output、acceptance と無関係な green command は pass しません。

## Sync boundary

`/cf:sync` は observed task Status と inline Receipt だけを surgical update します。Execution、approval、readiness、completion は捏造しません。
