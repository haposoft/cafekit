cf:specs — Process-First Flow

Layout mặc định là specs/<feature>/plan.md + các file task-NN-<slug>.md nằm cạnh nó. Một packet chỉ cần 1 owner cho 1 task, và 3 cổng quyết định để giữ scope, findings và done không trôi khỏi evidence.

C1 scope C2 findings C3 done Flat task files beside plan.md Inline canonical Receipt

Ba cổng quyết định

C1 — Scope

Chốt phạm vi tối thiểu trước khi viết plan. Nếu evidence mới làm scope sai, quay lại C1.

Hỏi: EXPAND, KEEP hay CUT.

C2 — Findings

Review adversarially từ fresh context. Dedupe finding, cap danh sách ở 15, và dừng sau tối đa 2 vòng giấy.

Hỏi: accept, reject, hay revise từng finding.

C3 — Done

Completion chỉ được chấp nhận từ output và receipts hiện tại. Không dựa vào cảm giác “xong rồi”.

Hỏi: evidence hiện tại có đủ để đóng task hay không.

Luồng 5 bước

1

Scout

repo evidence callers tests

Tìm code đã có, file thật, callers, exports và các điểm tái sử dụng trước khi viết plan.

2

Write plan.md

C1 decision EARS exclusions

Plan là index ngắn: scope decision, acceptance criteria kiểu EARS, explicit exclusions và task table.

3

Review adversarially

fresh context ≤ 15 findings ≤ 2 rounds

Phát hiện lỗi thật, không làm màu. Sau 2 vòng giấy, vòng tiếp theo phải có runtime evidence.

4

Execute one task

in_progress one owner real verification

Chỉ xử lý một task chưa block tại một thời điểm. Không nhảy sang task khác trước khi có proof thật.

5

Receipt + sync

inline Receipt Status: done sync state

Ghi canonical Receipt inline, đổi trạng thái thật, rồi mới xem task là done.

Packet phẳng

Layout bắt buộc

specs/<feature>/
├── plan.md
├── task-01-<slug>.md
└── task-NN-<slug>.md
Không tạo nested task directory cho packet mới.

Nhịp đọc

FileVai trò
plan.mdIndex ngắn, C1 decision, EARS criteria, exclusions, task table.
task-NN-*.mdOne outcome, one owner, one verification plan, one inline Receipt.

Trace criteria → task

Mỗi acceptance criterion phải có ít nhất một task và một proof command. Một task không có criterion là scope drift.

Criterion Task packet Proof
AC-01 task-01-<slug>.md Command: + output mới + Exit: 0
AC-02 task-02-<slug>.md Verification: PASS với output hiện tại
Nếu một criterion chưa map được vào task nào, quay lại plan thay vì nhét thêm prose vào task file.

Receipt + Stop gate

Canonical Receipt

## Receipt

Verification: PASS
Command: pnpm test -- --filter example
Exit: 0
Base: <runtime-derived base commit>
Head: <runtime-derived tree digest or commit>
```text
$ pnpm test -- --filter example
PASS example.test.ts
Tests: 3 passed, 3 total
```

Stop gate

  • Thiếu fenced output → không được done.
  • Thiếu Exit: 0 hoặc Verification: PASS → không được done.
  • Base/Head không khớp runtime hiện tại → receipt cũ.
  • Placeholder hoặc chỉ nói “PASS” bằng miệng → bị chặn.
Stop gate đọc lại receipt của mọi task done. Nó so Base và Head với runtime khi file task khác bản đã commit, và chỉ kiểm cấu trúc khi file đã commit, không đổi, và cây ngoài specs sạch. Gate phát hiện lệch chứ không phát hiện receipt bịa.

Develop + Sync

Develop

  • Chọn một task chưa block trong packet hiện tại.
  • Đổi Status: sang in_progress.
  • Implement đúng Outcome và Acceptance.
  • Chạy verification thật, rồi mới viết Receipt.

Sync

  • Chỉ ghi observed state của task file và Receipt.
  • sync-finalize chỉ dùng khi có fresh canonical PASS.
  • Không invent proof, approval, hay readiness.

Legacy compatibility

Phần này giữ các thuật ngữ cũ cho packet đã cài sẵn. Nó chỉ là nhánh tương thích, không phải đường chính cho v3.

planning_depth, assurance_level, lane, execution_tier, semantic_model Legacy adapter Giữ để tương thích, không author vào packet v3 mới.
