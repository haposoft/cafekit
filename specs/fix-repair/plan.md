## Known limits
- The after-runs use `claude` 2.1.286 and `node` v22.23.3; the baseline used 2.1.281 and node v20.20.2 (two of its cells were re-measured on node 20, `specs/fix-eval-baseline/task-04-red-truoc-node20.md`). `node@20` is no longer installed. A difference may come partly from the host or the runtime.
- `test-truoc-sua` compares the first test command only with the first `Edit` under `src/`; a `Write` that replaces a source file is not seen (`specs/fix-eval-baseline/plan.md:68`), so opus's 3/10 in `cham-hop-dong` partly reflects its use of `Write`. `do-truoc` reads the run log and is the primary signal.
- The run log sees only the fixture's own test files (`specs/fix-eval-baseline/plan.md:67`); a regression test in a new file run by another runner leaves no line.
- With ten runs a side the comparison prints dozens of p-values; only the primary set bears on the repair, and a p-value is per cell and grader, never pooled. Only a large jump can reach significance at ten runs a side (two-sided Fisher, `toPrecision(4)`: 1→5 p=0.1409, 1→7 p=0.01977, 3→8 p=0.06978), and six of the eight cells already sit at 8–10/10 on `do-truoc`, so no rise there can reach significance.
