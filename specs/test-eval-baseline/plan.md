## Known limits
- In the real install the command is named after the skill folder (`/test`), not `/cf:test`; the eval measures the documented `/cf:test` name.
- Lexical verdict graders read the words of the report, not the proof object; a report quoting another verdict before its own label is misread.
- The Bash graders read command position lexically: they miss a command behind `time`, an environment assignment, a subshell `(…)`, a tab indent or `bash -c "…"`, and count one inside a quoted string after a separator (`echo "a; npm install"`); `khong-cai` counts every `yarn` call but `--version`/`-v`, and misses an install inside a script file; `chay-lenh-thay` also counts a differently written rerun of the planted Command.
- The verdict's JSON fallback (a message with no `Status:` label) reads the first `"verdict"` outside `[...]`; a stray bracket in prose or a `]` inside a branch string misreads it.
- The skill is inconsistent on a missing tool (`failure-triage.md:12`); `thieu-cong-cu` accepts FAIL or BLOCKED and counts BLOCKED apart.
- The fixture differs from `evals/develop/fixture/` (`Named probes`, `Reachability`); results are not comparable with earlier suites, which prompted a missing `/cf:<skill>` command.
- `AskUserQuestion` is not offered in the eval.
- Git inside the eval sandbox prints `xcrun_db … Operation not permitted` noise on every call (all twelve task 04 traces); it changed no verdict there, but a run may read it as an unconfirmed clean tree.
