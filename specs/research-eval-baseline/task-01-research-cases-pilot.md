## The trace reader
`node evals/research/read-traces.mjs [--require-researcher] <result dir>...`, free. For each run of each directory: a run without a trace file is printed as `errored` with the first 120 characters of its `error` and skipped, or as `trace-missing` (bad) when it has no `error`. A run with an `error` and a trace (for example a timeout) is printed with `errored`, its error head and the `init=`, `tools=`, `web=`, `researcher=`, `report-src=` and `chars=` fields below, without the `agree` check (user decision on finding 11: its behaviour is shown, it stays out of every count). Every other run gets one line with:
- `init=` from the first `system`/`init` event: `agent` when `agents` holds a name matching `(^|:)researcher$`, `web` when `tools` holds both `WebSearch` and `WebFetch`, `skill` when `skills` holds exactly `cafekit-research:research`; a missing event or any of the three absent is bad. `host-research=` lists the other `skills` names that contain `research` (a host-bundled skill such as `deep-research`), or `none`.
- `tools=parent{…} sub{…}`: every `tool_use` block of every `assistant` event, counted by name, `sub` when the event's `parent_tool_use_id` is a non-empty string; `sub=` the number of such events.
- `web=<ok>/<calls>`: `WebSearch` and `WebFetch` calls, `ok` when a `tool_result` with that `tool_use_id` exists and its `is_error` is not `true`; for each ok call one indented `web-call <tool> <query or url> → <first 160 characters of the result>` line.
- `report-src=` for each `Agent` call whose `subagent_type` matches `(^|:)researcher$`: `error` when its `tool_result` has `is_error: true`; `sync` when its result text does not start with `Async agent launched`; `notification` when it does and a later `user` event's text (a string or text blocks) holds `<task-notification>` whose `<task-id>` equals the launch's `agentId:` value and a `<result>…</result>`; `launch-only` when it does and no such notification exists; `none` when there is no researcher call. The report text is the sync result or the notification's `<result>` body; `researcher=<sync + notification>/<calls>`. (In `claude` 2.1.281 an async launch returns `Async agent launched successfully … agentId: …` and the report arrives as `<task-notification><task-id>…</task-id>…<result>…</result>`; the pilots showed the report arriving instead as the `summary` of a `system`/`task_notification` event carrying the launch's `tool_use_id`, which the reader also accepts, and a sync result framed as `[Subagent hand-back]` with two-space indented lines, which the reader unframes.)
- `last-from=parent|sub|none` and `chars=`: the final answer rebuilt as the harness does — for every `assistant` event carrying text blocks, the answer becomes those texts joined with `\n`; `last-from` names the kind of the event that set it last.
- `agree=yes|no`: for each grader present in the stored run — every `regex` grader whose target is `last_message` recomputed on the rebuilt answer, every `tool_used` grader's count recomputed on all `tool_use` blocks (`JSON.stringify` of the input tested with its `input_match`) against the `called Nx` of the stored explanation, `khong-file-moi` recomputed from `new-files`, and `plan-giu-nguyen` recomputed on the kept file — each against the stored verdict; any difference is bad.
- `new-files=`: the files under the kept workspace (`chmod -R u+rwX` on `dirname(dirname(tracePath))`, then the one directory ending in `home/cwd`), `.git/` excluded, that the fixture does not hold; a missing workspace is bad. For case 3 also `plan-diff=none` or the first differing line number and its first 120 characters.
- `report=`: the report text of each `sync` or `notification` researcher call tested with every `last_message` regex grader of the case, `<grader>:y|n`, or `none`.
- For every primary grader the stored run failed, one indented `decisive <grader>:` line — the first 300 characters of the answer (newlines shown as `⏎`) for a `last_message` or `llm` grader, the first 300 characters of the first matching tool input for a `tool_used` grader, `plan-diff` for `plan-giu-nguyen`, `new-files` for `khong-file-moi`.
- For every `da-co-quyet-dinh` and `-agent` run, one `cap-check chars=<n> trich-adr=<stored> chon-drizzle=<stored> → ask|ok` line: `ask` when both graders passed and `chars` exceeds 4,000 (D-08).
Per directory it prints `runs= errored= timeouts=` (errors containing `timed out`, the separate over-reach figure) `timeout-chars=` (their `chars`, or `none`) `web-calls= web-ok= runs-with-web-ok= researcher-ok-runs= report-src=sync:a,notification:b,launch-only:c,error:d chars-median= disagreements=` and, for each `last_message` regex grader, `<grader>=<runs whose report matched>/<runs whose answer matched>`. It exits 1 on any bad run; with `--require-researcher` (task 01 only; in the baseline a cell without a report is a measurement) it also exits 1 when agent-path directories were given but none of their runs has a `sync` or `notification` researcher report.

## The ceiling and budget helpers
- `node evals/research/ceiling.mjs <sonnet|opus> <skill|agent> [results dir]` (default `../results/research` beside the script) reads the four `pilot-<dir>-<model>/result.json` of that model and path (the skill path's four directories, or the four `-agent` ones); each must exist with `partial: false` and one run; it prints `max(6, ceil(12 × the highest costUsd among them))` — `costUsd` already includes the judge (`cost_usd: U.costUsd+be` in the `claude` 2.1.281 binary) — and exits 1, naming the cause on stderr, on a missing or partial pilot or a value above 15 (sonnet) or 20 (opus). It exports that computation for `budget.mjs`.
- `node evals/research/budget.mjs <ceiling>... [--root <results root>]` (default root `../results` beside the script) sums the top-level `costUsd` of every `result.json` at any depth under `<root>/code-review/` and `<root>/research/` (including `-lan1` and `_pilot-lan*` directories), adds every ceiling given — one per cell about to start, so two cells started side by side are checked together — prints `spent=<x> next=<sum of ceilings> total=<x+sum> cap=230`, and exits 1 when the total exceeds 230. `node evals/research/budget.mjs --worst-case [--root <results root>]` prints `worst-case: spent=<x> remaining-ceilings=<y> total=<x+y> cap=230`, where `y` sums, over the sixteen `base-<dir>-<model>` cells not yet present, the ceiling of their model and path; it only prints and exits 0.
