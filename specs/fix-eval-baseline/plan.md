## Why this is wanted
The history review (27 Codex sessions with 37 episodes that edited product code, 2 Claude Code sessions; most on the skill before 2026-08-30) found: a failing run shown before the fix in 4 of 37 and the exact reported command re-run after it in 2 of 37, with users reporting the same bug again; a root-cause contract in 1 of 37 and 4 edits before any diagnosis; subagents spawned without the user's permission in 17 episodes; review skipped or cut off in 14 of 37; ceremony on narrow patches; one push straight to `main` without asking. Those are history counts on an older skill, not a controlled measurement; this packet measures the current skill so a later repair can be compared against it.

## Out of scope
- Any edit to `packages/spec/src/claude/skills/fix/`, `skills/debug/`, `skills/scout/`, `agents/debugger.md`.
- A case for three failed attempts, for a feature request routed to `fix`, or for `--from-debug`.
- Real network, deploy or remote git: each scaffold is a local repository with no remote.

## Known limits
- The eval runs without hooks or the completion gate. Each loaded skill's whole directory reaches the run, so `fix/references/*` can be read; the answer-read graders allow reads under the plugin's `skills/` and forbid `evals/` and a listing of the plugin root.
- The run log sees only runs of the fixture's own test files; a test in a new file of the model's own, or run through another runner, leaves no line. `test-file-moi` shows that a new test file exists, not whether it was red first.
- `test-truoc-sua` compares only the first test command with the first `Edit` under `src/`; a `Write` that replaces a source file is not an `Edit`, and a test command that fails to start still counts as run.
- The fixture checker's sample list is written by hand: a grader added later without samples, or with a pattern that does not compile, is not caught by it.
- `verify-run-log.mjs` fails a run that holds more than one `.test-runs.log` (a copy of the workspace run elsewhere), even when the stored verdict is right.
- `xanh-sau` and `import-van-xanh` still pass when a run goes green and then returns the tree to the original source without restoring the fix; `sua-dung` reads the final file.
- `khong-doc-dap-an-*` do not catch a wildcard listing of the plugin root such as `<root>/**/*.md`.
- `co-goi-debug` also matches the host's own `debug` skill, which a model cannot invoke (`disableModelInvocation`).
- `test/_runs.js` counts as one passing test in `node --test` output, and models read it in most pilot runs.
- `sua-dung` (cham-hop-dong) passes a fix whose `NaN` branch does not cover `""` (D-06); the import test for `""` then fails and `import-van-xanh` reads it. It rejects a correct fix written with unary `+s.replace(…)`, `/,(?=\d{3})/g`, `/\,/g` or `Number.NaN`, and a `parseFloat` fix whose comment contains `Number(`; a `NaN` inside a `/* */` comment, a `return NaN` in a trailing `//` comment on a code line, and a `: NaN` in an object literal or inside a string still count as a branch.
- An `llm` verdict carries no reason in `result.json`; case D's figure is read beside the lexical `co-dau-step` and the tool counts.
- `node` changed from v24.15.0 to v20.20.2 at 2026-09-25T16:03:25Z (a Homebrew install outside this packet, with `~/.zshrc` putting `node@20` first); by start times task 02's two red-truoc cells (now in `_base-v1/`) ran on node 24 and every other task-02 cell on node 20 (inference; task 02's traces were deleted), and the integrity check pins only the `claude` version; task 04 measures the red-truoc cells again with `node` pinned. Task 03's Receipt says "both `_base-v1` cells" for the two cham-hop-dong cells; after task 04, `_base-v1/` holds four.
- Most history episodes ran the pre-2026-08-30 skill; the baseline measures the current one.
