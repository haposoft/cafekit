# Test eval hard — measure cf:test on malformed packets, an unreachable test and its proof payload
Specs-Contract: process-first-ready-v1

## Scope decision (GATE-SCOPE — 2026-10-03)
- Existing:
  - `cf:test` classifies the packet before testing: a flat packet mixed with a legacy marker, or a task with malformed or duplicate fields, returns `BLOCKED` (`packages/spec/src/claude/skills/test/references/execution-strategy.md:13-42`). Missing or orphaned reachability fails even when the command exits 0 (`SKILL.md:66-70`); a reachability gap is `FAIL` (`references/failure-triage.md:14`). The `test-proof-v1` payload has 16 closed top-level keys, one branch per exact Named probe, counts that sum across branches, and `payload_sha256` over stable JSON without that key (`execution-strategy.md:92-165`); the payload goes to the controller and the human report must not carry the full JSON (`execution-strategy.md:200-206`).
  - No runnable `test-proof-v1` validator exists; only wording tests mention it (`packages/spec/bin/__tests__/develop-contract.test.js`, `packages/spec/scripts/run-skill-self-tests.mjs`). An offline check of the 80 runs of `specs/test-eval-baseline` (2026-10-03, $0): 39 printed a payload, 38 of them with a matching digest under sorted-key compact JSON; 41 said the payload was ready without printing it.
  - `evals/test/` (fixture, four cases, graders, `check-fixtures.sh`, `save-runs.mjs`, `compare.mjs`, `budget.mjs`) and `evals/run.sh --plugin-name cf` exist from `specs/test-eval-baseline`; all 80 of its runs loaded the skill.
- Minimum change: three new cases in `evals/test/`, an offline payload checker, tool updates for the new cases and this packet's budget, pilots, and six cells × 10 runs; a report without a conclusion.
- Expansion signals: none over the threshold.
- User decision: KEEP — cases `tron-legacy`, `trung-probe`, `khong-cham-code`; a run that does not print its payload is counted apart, not as wrong; cap $100.

## Out of scope
- Any change to `cf:test`, `test-runner` or other suites; symlinked or field-missing tasks; UI modes; legacy routing beyond the mixed case; pushing; publishing.

## Known limits
- The verdict and Bash graders read words, as in `specs/test-eval-baseline`; its Known limits apply.
- "Stable JSON" is read as sorted-key compact JSON (`[UNVERIFIED]`).
- `khong-cham-code`'s `neu-nguyen-nhan` reads words: it can accept a `BLOCKED` that restates the declared Reachability line in other words (`from task`, `unverified`, `pending`, `chưa chạy`) and miss a correct one that contains `would`, `declared` or `PASS`; every `khong-cham-code` run passing `joint` through the `BLOCKED` branch is hand-read in task 04.
- `chay-dung-lenh` reads command position lexically: a quoted string inside a `node -e` script that holds `; node --test test/greet.test.js` counts as a run (task 03: `pilot-trung-probe-opus` counted 2 for 1 real run); in `khong-cham-code`, where it enters `joint`, every run whose only match sits inside such a script is hand-read in task 04.
- Changing `evals/test/` changes the digest that `specs/test-eval-baseline` tasks 04–05 guard, so those closed Commands no longer re-run; their Receipts are unaffected.
- `AskUserQuestion` is not offered in the eval; git in the sandbox prints `xcrun` noise.
