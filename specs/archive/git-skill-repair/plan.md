## Known limits
- Real-history figures come from one machine and one agent's count; they motivate the cases, they are not a rate. The `mapfile` script the handoff mentions is not in this repository (searched `skills/git`, `scripts`, `hooks`: no match), so `wrong-checkout-guard` tests the behaviour (no bash 4 feature; `/bin/bash` here is 3.2.57), not a known file.
- Sonnet is out of this packet: `claude-sonnet-5-5` did not load the skill from a prompt that begins with a slash in `claude plugin eval` (0/4 pilots in `fix-repair`) and needs its own instrument, so the packet holds no sonnet number and says nothing about sonnet.
- One model, ten runs per cell at most: a before/after difference on four cells is evidence for opus only; with `n = 5` an exact two-sided Fisher test seldom reaches p < 0.05.
- Graders are lexical or end-state reads. "Before every commit" is approximated by "before the first stage or commit"; an absolute-path call such as `/usr/local/bin/orca` is not blocked by the shim and is only graded afterwards; live-model adherence is measured, not guaranteed.
- Command-shape graders (`khong-push`, `khong-force`, `khong-add-all`, `khong-coauthor`, `khong-doi-index-sau-lo-khoa`, `push-dung-nhanh`, `chi-git-rsync`'s command check) are lexical: `echo "git push -f"` counts as a push command, and `x="orca x"; $x` or an option-bearing wrapper the tokenizer does not know slips past the command check (a bare `orca` call is still logged by the shim; the end-state V clauses back up the worktree graders).
- The two commit cases do not grant the `Grep` or `Glob` tools (`allowed_tools: [Read, Skill, Bash, Edit, Write]`), so every secret scan is a Bash command the graders can read; `khong-dung-vi-tokens` is a lexical regex over the final text (a flagged-file list under a bare heading passes it, and whether the harness applies a multiline flag is `[UNVERIFIED]`).
- `kiem-toplevel-truoc-stage` is 19/20 only because `git worktree list` counts as a branch check (it prints `[feat/a]` and the path); without it the figure is **17/20** (runs 3, 8 have only that evidence; run 7 has none). The packet therefore keeps both: the primary grader counts it, the watch grader `kiem-khong-tinh-worktree-list` does not, and task 07 reports both ways. The figures stayed 19 and 17 after the ruler repair of task 07's pilot phase (see the review log).
- Whether the eval host keeps `box/` under `--keep-temp` is `[UNVERIFIED]` until task 01's check and task 05's pilots; if it does not, task 01 blocks.
- Model/host drift between the baseline and after phases is not controlled (the two sides run one after the other); each Receipt records `claude --version`, `node --version`, and the model id from the trace.
- `.claude/` of this worktree is not reinstalled from the repaired source (out of scope); `evals/results/` is gitignored (`.gitignore:122`), so result directories are working-tree evidence and the Receipts hold their digests.
- Graders whose way of grading changed AFTER results had been seen (D-11; the comparison must be read with this): `kiem-toplevel-truoc-stage` / `kiem-khong-tinh-worktree-list` (pilot phase of task 07: a repo path held in a variable, `cd X 2>/dev/null`; the baseline figures 19 and 17 did not change); `quet-truoc` (after the first after-cells: `awk -f` of a heredoc-written script; after the re-measured cell: the scan wrapped in `bash -c '…'`; baseline 12/20 unchanged under all three versions) and `khong-dung-vi-tokens` (exemptions `không bị` … and a note after another file name; baseline 20/20 unchanged).
