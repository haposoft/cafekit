The installer copies the whole directory per platform through `copyRulesDirectory` (`packages/spec/bin/phases/claude-runtime.js:260-277`, gated by the `rules` capability, enabled for both platforms at `bin/lib/context.js:92,119`): the Claude copy passes through `normalizeSourcePaths` (identity unless the text contains a `packages/spec/src/` path — `bin/lib/copy-utils.js:28-39`), the Codex copy through `normalizeCodexBody` (`bin/lib/codex-install.js:288-298`). The npm `files` whitelist already includes `src` (`packages/spec/package.json:18-20`). Existing guards: four ordinary static probes over rule files in the harness `checks` array (`packages/spec/scripts/run-skill-self-tests.mjs:4231,:4665,:4679,:4916`) — no rule has a mutation checker; installed Claude/Codex rule parity (`packages/spec/bin/__tests__/codex-native.test.js:3107-3115`); the packed-tarball `REQUIRED_PAYLOAD` list (`packages/spec/bin/__tests__/package-inventory.test.js:110-145`, asserted by `assertCleanInventory` at `:272-275`). No test pins the count or exact set of rule files, and no line/byte budget covers `rules/`. The reference rules `~/Desktop/cafekit-ref/.claude/rules/review-audit-self-decision.md` (34 lines) and `process-management.md` (40 lines) have no CafeKit counterpart: nothing shipped covers background-process hygiene, audit-versus-decision precedence, or ID-free code artifacts.
- Minimum change: add two rule files to `packages/spec/src/claude/rules/` carrying the reference guidance in CafeKit vocabulary — `review-audit-self-decision.md` (verified decisions stand unless the audit brings new evidence or changed context, naming the verification source when rejecting a concern; explicit user decisions, including the C1/C2/C3 dispositions defined in `workflow.md`, are never silently undone — a reversal proposal presents the original decision, the audit concern, the trade-off, and concrete options, then waits for the user; identify what the code actually stores, protects, or exposes before applying a security or robustness finding; scout the repository before asking, deferring ask-back conditions to `hapo:ask`; do not add plan, phase, CP/AC, audit, or finding IDs to new code comments, migration names, test names, or commit messages) and `process-management.md` (track command, PID, port, worktree; check for an owner then reuse or stop it; deterministic port per project or worktree, stopping the stale owner instead of taking another port; stop what you started before its task, session, or wave worktree ends; reconcile periodically; clean stop before hard kill; stop only processes you own and never a broad kill pattern). Add one consult bullet naming both rules to the Codex runtime template, written in Codex-native vocabulary, so Codex has a real read path. Guard the pair with two ordinary static probes (required anchors plus forbidden negation patterns) and one transform-safety probe, then assert installed parity for both runtimes and packed payload.
- Expansion signals: none — one subsystem (shipped rules), six touched files, two sequential tasks.
- User decision: **KEEP** — port exactly the two reference-only rules; do not fold reference deltas into the six thematically paired rules, whose routing and state machinery differ by design.
