# Grok CLI runs the CafeKit gates through the Claude install
Specs-Contract: process-first-ready-v1

## Scope decision (C1 — 2026-09-08)
- Existing: grok 1.0.13 loads `<project>/.claude/settings.json` hooks, `.claude/skills`, `.claude/rules`, and `CLAUDE*.md` on its own through `[compat.claude]`, every cell default `true`; `grok inspect` in this repository lists CafeKit's hook groups as `project [claude]`, matcher `Read|Write|Edit|MultiEdit|Bash|Glob|Grep` included. It sets `CLAUDE_PROJECT_DIR` for every hook as an alias of `GROK_WORKSPACE_ROOT`, aliases Claude tool names in matchers, and accepts the Claude output vocabulary unchanged. The hooks are already portable (`src/claude/hooks/lib/runtime-dir.cjs`). `src/omp/hooks/lib/omp-tool-names.cjs` is a tool-name alias table of the same kind grok needs.
- Minimum change: one shared payload reader that accepts grok's camelCase envelope and returns the snake_case Claude shape the hooks read; routed into thirteen of the fourteen hooks that parse stdin, the Stop gate needing only a second spelling at its loop guard; the two exit-2 denials emit a JSON deny carrying the full reason; omp's lowercase aliases move into that one table so the omp overlay shrinks to `privacy-block.cjs`; `--platform grok` installs the Claude runtime and prints the trust reminder; documentation records what grok can and cannot carry. No `.grok/` directory.
- Expansion signals: about twenty-five touched files, above the eight-file threshold; one subsystem, since every hook edit is the same one-line routing and every other file follows from it.
- User decision: C1 KEEP — normalize at the source. EXPAND (`.grok/hooks/<kit>.json` plus an envelope shim, the AgentKit approach) was declined: with `[compat.claude] hooks` on by default it runs every hook twice, once with the wrong payload. CUT was declined.

## What grok can and cannot carry (C2 finding 2, 2026-09-08)
Grok has exactly four control-flow channels: a `PreToolUse` deny, a `UserPromptSubmit` block, a `Stop`/`SubagentStop` block, and exit 2. Everything else is passive — "every other event is passive: its output is recorded but does not change control flow" (`32360`, `32425`) — and for an allowing `UserPromptSubmit` hook "an allowing hook's stdout / `additionalContext` is discarded rather than added as context" (`32587`).

So under grok this packet repairs the gates and cannot repair the reminders. These hooks keep running and keep being normalized, but the model never reads their output: `rules.cjs`, `spec-state.cjs`, `session.cjs`, `docs-sync.cjs`, `state.cjs`, and the allowing path of `secret-output-guardrail.cjs`. They are normalized anyway because it costs one line each and keeps one code path for every host; the packet claims no reminder delivery under grok, and no acceptance criterion uses their stdout as proof.

## Why this is a repair, not a feature
Today any project installed with `--platform claude` and opened in grok runs CafeKit's hooks with a payload they cannot read.

- `privacy-block.cjs:205` reads `data.tool_name`, gets `undefined` under grok's `toolName`, extracts no paths, and exits without an `ask`: **the privacy gate is silently open**.
- `spec-gate.cjs:83` reads `payload.stop_hook_active`, gets `undefined`, and loses its loop guard; grok's own cap ends the turn "after **8 continuations**" (`32508`).
- `inspect-block.cjs:92` and `task-scaffold-guard.cjs:75` print their deny reason with `console.log` and exit 2. Grok takes "the first stderr line (capped) … as the deny reason when the JSON carries none" (`32496`), and there is no stderr, so the model is blocked with no reason at all.
- `completion-authority.cjs` is registered without an argv mode on both `UserPromptSubmit` and `Stop`; with `hook_event_name` undefined its mode falls back to `--stop` (`completion-authority.cjs:140`), so under grok it runs the stop path on **every user prompt** and can emit `{"decision":"block"}`, which grok honours as a prompt block (`32362`).

## Verified contract (grok 1.0.13)
Regenerate the evidence file with `strings -n 6 ~/.grok/downloads/grok-1.0.13-macos-aarch64 > grok-strings.txt`; bare numbers below are lines in that file, each quoted by its anchor phrase so a shifted dump stays checkable.

- Sources: `<project>/.grok/hooks/*.json` and `<project>/.claude/settings.json` plus `settings.local.json`, both requiring project trust via `/hooks-trust` or `--trust`; untrusted project hooks are silently skipped (`32330`). `[compat.claude]` cells `skills`, `rules`, `agents`, `mcps`, `hooks`, `sessions` all default `true` (`31096`).
- Events: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionDenied`, `Stop`, `StopFailure`, `StopCancelled`, `Notification`, `SubagentStart`, `SubagentStop`, `PreCompact`, `PostCompact`, `SessionEnd`; unrecognized names are skipped so a Claude settings file still loads.
- Control flow: only the four channels above (`32360`, `32425`).
- Stdin envelope, camelCase: `hookEventName` (snake value such as `pre_tool_use`), `sessionId`, `cwd`, `workspaceRoot`, `timestamp`, `permissionMode`, `promptId` (`32456`); tool events add `toolName`, `toolInput`, `toolUseId`, `toolInputTruncated`; `Stop` adds `stopHookActive`, `lastAssistantMessage`, `reason`; `PostToolUse` carries `toolResult`, not `tool_response`; subagent identity is `subagentType` (`32578`). The binary's own camel/snake pair table includes `transcriptPath`/`transcript_path` (`28215`).
- Tool names: the documented matcher aliases are `Bash`→`run_terminal_command`, `Read`→`read_file`, `Edit`/`Write`/`MultiEdit`→`search_replace`, `Grep`→`grep`, `Glob`/`ListDir`→`list_dir`, `WebSearch`→`web_search`, `Task`→`spawn_subagent`, and "a matcher keeps its original name too" (`32405`-`32419`). The binary's internal tool-name pool additionally contains `write`, `delete_file`, and `PowerShell` (`28227`), so grok's file-creating tool is `write`, distinct from `search_replace`. `read_file` input uses `path` (`33496`).
- Output: `PreToolUse` reads top-level `decision` or `hookSpecificOutput.permissionDecision`, the latter canonical when present (`32473`); **"a `deny` decision in stdout JSON is honored regardless of exit code"** (`32498`). `Stop` blocks on `{"decision":"block","reason"}` (`32502`) or exit 2 with stderr as feedback. `UserPromptSubmit` blocks on exit 2 or `{"decision":"block"}` (`32362`).
- Failure mode: every hook failure — timeout, crash, malformed output, any exit code other than 0 or 2 — is fail-open (`32402`, `32425`). Default timeout 5 s, 600 s for `Stop`/`SubagentStop` (`32402`).
- Environment: `GROK_HOOK_EVENT`, `GROK_HOOK_NAME`, `GROK_SESSION_ID`, `GROK_WORKSPACE_ROOT`, `CLAUDE_PROJECT_DIR` on every hook (`32615`); `${VAR}` in `command` is expanded once by the runner (`32451`).
- Matchers are regular expressions and are tested against the tool name on tool events, the start source on `SessionStart`, the subagent type on `SubagentStart`/`SubagentStop`; a matcher on `Stop` or `UserPromptSubmit` is ignored with a warning (`32398`).
- AgentKit (`ak`) registers `.grok/hooks/<kit>.json` commands as `node ${GROK_WORKSPACE_ROOT}/.grok/hooks/<kit>/agentkit-grok-envelope-shim.cjs <hook>` and translates camelCase→snake_case, `run_terminal_command`→`Bash`, `pre_tool_use`→`PreToolUse`, exit 2→`{"decision":"deny"}` in a ~211-line fail-open shim [from the 2026-09-08 research session; the installed copy was in a discarded temp project].

### `[UNVERIFIED]` — C2 decision: recorded as limitations, not settled by a live run
The user declined spending a grok turn to settle these. Each names the command that would settle it; no acceptance criterion depends on any of them.
- **Matcher `"*"`**: `src/claude/settings/settings.json` uses it for `SubagentStart` and `PreCompact`, but grok documents matchers as regular expressions (`32398`) and its own hooks use `.*`. `grok inspect` shows the groups loading, which is not the same as matching. If they never match, `agent.cjs` and `precompact.cjs` never run under grok. Settle: register a `SubagentStart` hook with matcher `*` writing to a file in a throwaway repository and run one grok turn with a subagent.
- **`grep` / `list_dir` input schema**: `inspect-block.cjs:91` gates on `toolInput.pattern`; grok's key for that argument is not documented in the dump. Settle: the same envelope dump on a real `grep` call.
- **Field names for `prompt`, `source`, `trigger`, `agent_id`**: the common-field list (`32456`) omits them and the dump does not name grok's spellings. The reader accepts both the Claude spelling and the obvious camelCase twin, so a match works either way, but neither is proven. Settle: the same envelope dump on `UserPromptSubmit` and `SessionStart`.

## Out of scope
- A `.grok/` runtime directory, `.grok/hooks/*.json` registration, or an envelope shim. Users who set `[compat.claude] hooks = false` are not served; documented.
- Reminder delivery under grok, as recorded above. The six context-injecting hooks are normalized but prove nothing.
- **`usage.cjs` (C2 finding 8)**: it reads the Claude Code OAuth token from the macOS Keychain (`usage.cjs:54`) and calls `api.anthropic.com` (`usage.cjs:122`), and its `isUserPrompt` flag lowers the fetch interval from 300 s to 60 s (`usage.cjs:43-45,170`). Normalizing its payload would make a non-Claude runtime touch Claude credentials five times as often for output grok discards. It is left unrouted and keeps behaving exactly as it does today.
- `state.cjs` transcript parsing under grok: `transcriptPath` is deliberately **not** mapped, so `state.cjs:115` keeps skipping silently rather than streaming a grok session file of unknown format. Recorded as a limitation.
- `status.cjs`: it does parse stdin (`status.cjs:91-94,459`), but grok's `[compat.claude]` has no statusline cell (`31096`), so grok never invokes it.
- Launching grok in tests. Every proof runs the real hooks as child processes with envelopes built from the documented shape.
- README platform lists, matching the omp packet's exclusion.
