# Remove the usage hook
Specs-Contract: process-first-ready-v1

Packet 1 of 3 in `plans/20261006-hook-cleanup-roadmap.md`. Work context: worktree `../cafekit-chore-remove-usage-hook`, branch `chore/remove-usage-hook` from `dev` 60ba450; commands run from `packages/spec/` unless stated.

## Scope decision (GATE-SCOPE — 2026-10-06)
- Existing: `usage.cjs` is registered on UserPromptSubmit and PostToolUse `Edit|Write|MultiEdit` (`src/claude/settings/settings.json:71,116`), shipped by `src/claude/migration-manifest.json:134`, and bridged for omp (`src/omp/extensions/cafekit-bridge.mjs:44,46`); Codex ships no usage hook. It reads the Claude Code OAuth token from the macOS Keychain (`src/claude/hooks/usage.cjs:54`) and calls an undocumented endpoint (`usage.cjs:11-12`) to write `ck-usage-limits-cache.json`. The statusline already prefers the payload's `rate_limits` and only falls back to that cache (`src/claude/status.cjs:31,572-578`). Upgrade pruning exists for Claude only: `obsolete.runtimeFiles` is deleted unconditionally — pristine or user-modified alike — by `removeObsoleteClaudeRuntimeFiles` (`bin/phases/claude-runtime.js:168-190`, returns early for any other platform), and `obsolete.settingsHookCommandSubstrings` drops any `.claude/settings.json` hook whose command *contains* the substring (`bin/phases/claude-settings.js:21,42-46`); both already carry `hooks/skill-router.cjs`. omp copies `runtime.files` hooks with no obsolete step (`bin/phases/omp-runtime.js:48-77`). `src/claude/hooks/lib/context.cjs` holds a second cache reader (`readUsageCache` `:221-232`, used by `buildUsageSection` `:304-335`) but no hook requires that library. The runtime schema has `additionalProperties: false` and declares `usage` (`src/claude/runtime.schema.json:75`).
- Minimum change: stop installing and registering `usage.cjs` on Claude and omp, prune it on upgrade on both, remove both cache readers (`status.cjs` fallback and `context.cjs` `readUsageCache`/`buildUsageSection`), keep the `usage` config key valid but deprecated, update the self-test anchors, package docs and the `cafekit-web` pages that name it.
- Expansion signals: about 20 files touched (above eight, mostly docs), one subsystem, no new service.
- User decision: KEEP (three packets, this one first); remove the hook and both cache readers; Claude Code without `rate_limits` loses the quota segment.

## Out of scope
- Deleting `src/claude/hooks/lib/context.cjs` itself (only its usage reader goes; the rest of the dead library is a separate cleanup).
- Removing the `usage` key from `runtime.json` or the schema (an existing user file carrying it would fail `additionalProperties: false`).
- Packets 2 and 3 of the roadmap; `spec-gate` latency; Codex (no usage hook).
- Pruning `usage.cjs` entries a user added to `.claude/settings.local.json` or `~/.claude/settings.json` (the installer manages only `.claude/settings.json`); the changelog tells the user to check them.
- A user-modified `.omp/extensions/cafekit-bridge.mjs` is preserved by the installer and keeps its old dispatch list; once `.omp/hooks/usage.cjs` is pruned, that dispatch finds no file. Documented, not repaired.
