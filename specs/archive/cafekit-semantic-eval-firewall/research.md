# Research: cafekit-semantic-eval-firewall

Research exists only because this uncertainty can change requirements or design. Record evidence and a decision; do not use this file as a generic discovery log.

## Uncertainty

- How should CafeKit stop case patching and false-ready promotion while fixing baseline lifecycle deadlock after advance, repair_round contradictions, C1/C9 circular digests, incomplete IR contracts, and allowlist gaps—without inventing PASS or coding while ready=false?

## Evidence Summary

- Independent review FAIL found: post-advance baselineCommit=HEAD then freeze banned (deadlock); repair_round wording mixed FAIL and BLOCKED; C1 required digests that C9 also bound (circular); bootstrap demanded release digests before any release; allowlist omitted run-skill-self-tests and benchmark-adjudicate; authority rotation required ChangeProposal against itself; IR dual-run lacked normalize/equality/mode authority contract; V7 entrypoint/anchor drift; public fixtures lacked field schema; R2 duplicate validate anchors.
- `packages/spec/src/claude/scripts/spec-readiness.cjs` still promotes ready true on legacy 2-key shape without verdict/blocker storage.
- `packages/spec/src/claude/scripts/validate-spec-output.cjs` still uses closed legacy semantic_review fields until C2 cutover.
- `packages/spec/package.json` scripts are test, test:package, test:secrets, test:policy; version `0.16.0-rc.4` must be preserved by surgical script edits (not in this authoring turn).
- `packages/spec/scripts/run-skill-self-tests.mjs` is the aggregate test entry; discovery + --require-semantic-test is the reachability invariant.
- MODEL_FIELDS for semantic_model are exactly version, criteria, anchors, design_records, verification_definitions per `spec-semantic-model.cjs`.
- Approved sources: `specs/_shared/Research-stop-case-patching-specs-2026-08-15.md`, `plans/20260815-cafekit-semantic-eval-firewall.md`.

## Decision

- Baseline authority: discriminated union bootstrap vs released; empty-protected-path validity is authority-state conditioned (bootstrap always exits 2, released always valid), not a blanket HEAD-equality rule; reserved-path exclusion for release-baseline.json happens before diff derivation and takes precedence over the generic benchmarks/ prefix; advance invalidates freeze; named reserved transitions only for release-baseline.json.
- C1 semantic-only; C9 sole digest binder with authority digest+generation; C12 ReleaseReceipt (new, owned R5-01) gates advanceBaseline with an externally computed, non-circular digest; no circular digests anywhere.
- repair_round is the C13 `semantic_review_history` attempt_index (count of prior FAIL entries in the durable, append-only lineage); verdict PASS|FAIL separate from lifecycle_disposition CONTINUE|BLOCKED; caller-supplied repair_round/history/lineage_id is rejected, not "ignored or rejected".
- C11 complete normalize/equality/disagreement/mode authority, with an explicit command/inspection tagged-union method and one exact ASCII ordinal comparator (not localeCompare) for all sorts.
- D1 sole allowlist covers `packages/spec/scripts/` and `packages/spec/bin/__tests__/` by directory prefix (not per-file enumeration), so run-skill-self-tests.mjs, benchmark-adjudicate.mjs, candidate-isolation.mjs, package-inventory.test.js, validator-grounding.test.js, specs-v2-validator-grounder-contract.test.js, and develop-contract.test.js are all covered without a divergent list; excludes .cafekit-release; reserved C10 for baseline file.
- Public fixture field-level schema; V7 entrypoint is the real, existing run-skill-self-tests.mjs (not the not-yet-created metamorphic schema); single R2 validate owner-write anchor.
- Preserve public 8, dual-run, ownership, legacy bridge, and ready=false; the current graph has 10 tasks after adding lifecycle-only R1-03 activation authority.

## Round 3 (fresh review r5) — general invariant classes, not per-fixture patches

- Ownership contention must be checked globally and pairwise across every `coordination.boundaries` entry (I7), not only within one boundary; a systematic scan found 9 cross-boundary same-target write pairs (only 5 had been reviewed before). Because a `dependency` boundary carries one `deliverable`, the provable unit is one boundary per producer/consumer pair, not one per shared path.
- The change firewall must gate unproven change, never freeze legitimate evolution (I8): C1 is now a tagged `change_intent` — `benchmark_remediation` or `authorized_evolution` (fresh spec + independent PASS + exact write-set + rollback, never a bypass for an un-adjudicated benchmark failure).
- Bootstrap trust root must be exact, not a merge-base guess: new C14 BootstrapAttestation with attested `baseCommit`/`headCommit`.
- C13 dedupe must cover the whole lineage, not only the latest entry; "no third attempt" wording was self-contradictory against `attempt_index` 0/1/2 already being the first/second/third attempt — corrected everywhere.
- C12 `artifactDigest` must be independently re-hashed from a real `.tgz` at an explicit, restricted path, not merely declared.
- C10 `previousBaselineDigest` provenance must be exact (sourced from the authority record actually loaded, never self-declared), with an explicit honest-agent-only threat model.
- B1-unshipped needed a written rationale (source-only release governance, never runtime payload) — now settled in D9, not open.
- IR promote-transition needed an exact gate list and a named non-sticky rollback, not just "after gates."

## Round 4 (fresh review r6) — durable ledger, exact boot-window, epoch-scoped attempts

- A benchmark failure had no durable record: an `authorized_evolution` proposal could edit a protected path with an open, un-adjudicated framework regression sitting on the same path and nothing tracked that fact across runs. New **C15 BenchmarkFailureLedger** (`opened`/`classified`/`resolved` events, C10-identical generation+digest-chain provenance) is the durable record; it is reserved under D1 exactly like `release-baseline.json`, bound into C9 freeze digest+generation, and gates `authorized_evolution`/`benchmark_remediation` with no bypass. Only `benchmark_remediation` may carry `failure_ids`; `authorized_evolution` has no such field and is refused unconditionally on any open-entry intersection — never passed through by citation.
- The prior bootstrap sequence implicitly exempted "R0 first, then everything after goes through the choke," which left the exemption boundary and the PASS backing `bootstrapReviewDigest` under-specified — two implementers could plausibly draw the line differently. **D11/I9** now name an exact, narrow, sequence-bound boot-window: legacy-bridge PASS exempts build-only work on exactly R0-01/R1-01/R1-02 (no invoke, no freeze, no publish); a fresh, real, post-C2/C13-cutover review must PASS on the current digest, seeding `semantic_review_history` at `sequence 0`/`review_epoch 0`; only then does `bootstrapBaseline` activate live gating, C14's `bootstrapReviewDigest` binds to that seed entry (not the disposable legacy bridge report), and R2-01..R6-01 implement through the live choke via `authorized_evolution` bound to that same entry. The final freeze/receipt/`advanceBaseline` never runs until every task has landed and every D8 gate has passed — no partial R0/R1 publish.
- `attempt_index` as "count of prior FAIL entries in the whole lineage" never reset after a PASS, which is inconsistent with a lineage that keeps reviewing after promotion (e.g., for later `authorized_evolution` work): a single early FAIL would permanently shrink the remaining attempt budget for every future review cycle. New `review_epoch` (count of prior PASS entries) scopes `attempt_index` to FAILs since the last PASS in the same epoch; a PASS closes its epoch, the next entry opens `review_epoch + 1` at `attempt_index 0`; a BLOCKED epoch (index 2 FAIL) is still terminal and is never reopened outside a new lineage (I6/I10). Whole-lineage digest dedupe is unchanged.
- `authorized_evolution`'s `independent_pass_receipt_digest` only had to equal *some* PASS entry in the lineage, independently of the separate `spec_semantic_digest`-equals-current check — a genuinely stale PASS (reviewing an earlier, since-changed digest) could still be cited. Closed by requiring the referenced PASS entry's own stored `semantic_digest` to equal the current `spec_semantic_digest`, not merely an older PASS left over from a prior revision.
- C14's `treeDigest` field was redundant: `baseCommit` already pins the tree, so `bootstrapBaseline` can and now does re-derive the protected tree digest itself via `computeProtectedTreeDigest` rather than trusting a caller-attested copy. Removed from C14's shape, schema, and every referencing task.
- Contradiction sweep beyond the four named decisions: C15 ownership/ordering reuses the existing R0-01→R4-01 and R0-01→R5-01 dependency edges (no new boundary needed, one deliverable per producer/consumer pair per I7); C9 freeze now also binds C15 ledger digest+generation so any ledger event stales an existing freeze; the boot-window's C14 attestation spans the full R0-01+R1-01+R1-02 diff (never empty/partial) and `bootstrapBaseline` refuses to run before the seed PASS exists; C1/C14 remain non-circular (`failure_ids` is an opaque label, never a digest); a BLOCKED epoch stays terminal with no new recovery path; C12 gained `resolvedFailureIds` (sorted, non-empty only when resolving); the task DAG and every write anchor were re-derived from markdown via the real `spec-semantic-model.cjs` parser and re-scanned globally and pairwise — no new same-target write conflict; the ledger stores only digests/paths/labels, adding no privacy or ship-boundary exposure.

## Round 4 amendment — C12/C15 crash-ordering, idempotent resume, replay precision

- The original R6-D1 text had `advanceBaseline` verify-then-invoke `resolveFailure` before describing the C10 write, which read as `resolveFailure` (a ledger mutation) possibly happening before or interleaved with the C10 rotation. Since C9 binds the ledger's own digest+generation into the freeze, an early ledger mutation would stale the very freeze the same operation still needed to validate against, and a crash between the two file writes had no defined resume path — a real partial-write hazard, not a hypothetical one.
- Fixed by an exact order, never reordered: `advanceBaseline` (C10, `release-baseline.json`) always runs first and is idempotent by receipt digest (a matching current `releaseReceiptDigest` is a no-op, skipping freeze/candidate re-validation entirely — that's precisely the state after a crash following a successful rotation); it never invokes `resolveFailure` itself. Only after it returns success does the caller (R5-01) invoke `resolveFailure` (C15, `benchmark-failure-ledger.json`) per resolved id; `resolveFailure` independently re-loads the current C10 authority and refuses unless this exact receipt is already the published one — a contract-level guard, not just a caller convention, so a reordering bug cannot record `resolved` for an unpublished release. New invariant **I11** names this generally; no cross-file transaction is claimed or faked — correctness comes from strict order plus two independently idempotent, fail-closed single-file writes.
- Mid-turn correction: the first pass at V8/R5-01's negative-path prose said "resolveFailure accepted for ... an already-resolved id" as a blanket defect, contradicting the idempotent-replay rule just stated. Corrected to distinguish exactly: same id + matching `release_receipt_digest` → idempotent no-op success (correct, not a defect); same id + mismatched digest → refused, exit 2 (the actual defect if accepted). Synced across design.md (C15 contract text, Errors-and-Recovery table, V8), requirements.md (R6.7), task R5-01, and the spec.json projection.

## Round 5 (fresh review R7, verdict FAIL: 2 Critical, 1 High, 1 Medium, 1 Low)

- **Critical — C15 resolve-bypass.** `C12.resolvedFailureIds` had no binding to what the freeze/candidate actually proved was being remediated; `resolveFailure`'s own precondition only checked classification/unresolved state and current-authority publication, neither of which ties the id to *this specific release's* protected change. A release could cite an unrelated open `framework_regression` failure and mark it resolved. Closed by a new C9 field `remediatedFailureIds`: `createFreezeManifest` copies the accepted `benchmark_remediation.failure_ids` exactly, only after the gate has proven the path-union invariant for those ids; always empty for `authorized_evolution`/`no_protected_change`; bound into `candidateDigest`. `C12.resolvedFailureIds` must now be the exact sorted-set equal of `remediatedFailureIds`, verified by `advanceBaseline`. New invariant **I12**. No new proposal store — C9 remains the sole vehicle.
- **Critical — C1 `authorized_evolution` used the wrong fields.** The durable-spec check read `authoring.requirements`/`authoring.design` as if they encoded `planning_depth` — but the real project schema keeps these as an independent `draft|validated|absent` lifecycle-state enum, entirely separate from `workflow_policy.planning_depth` (`None|Compact|Full`). Verified directly against `workflow-policy.cjs`/`validate-spec-output.cjs`. Corrected: durable-spec test now reads `workflow_policy.planning_depth`; `authoring.requirements`/`authoring.design` = `validated` is checked separately, never as a stand-in.
- **High — legacy bridge artifact provenance.** C14's `baseCommit` ("the commit at legacy-bridge time") was never durably captured anywhere, leaving `bootstrapBaseline` to reconstruct it heuristically from git history whenever it actually runs — exactly the merge-base-guess risk this spec otherwise bans. Closed: the bridge report now captures an exact `bootWindowBaseCommit` field (real `git rev-parse HEAD` at bridge time, before any code lands); C14's `baseCommit` must equal it exactly, verified by `bootstrapBaseline` reading the artifact directly.
- **Medium — C4 enum drift.** C4 declared `planning_depth enum None|Compact|Standard|Full`; the real source (`workflow-policy.cjs`'s `PLANNING_DEPTHS`) is `['None', 'Compact', 'Full']` — no `Standard` anywhere in the project. Corrected.
- **Low — V9 reachability.** V9 pointed its reachability entrypoint at `plans/20260815-cafekit-semantic-eval-firewall.md` (a decision record, not code) while every other V points at a real executable. Moved to `validate-spec-output.cjs` (the actual ownership-contention validator) via a new R6-01 read anchor and a direct R1-01→R6-01 dependency edge (read-only, no write conflict).
- **Mid-turn sweep catch — live C1/C9 contradiction.** "C1 never holds digests; C9 sole binder" was false as literally stated: `authorized_evolution` legitimately carries `spec_semantic_digest`/`independent_pass_receipt_digest`. Corrected everywhere to the precise rule: C1 never holds the *release-candidate lifecycle binding* digests (baseline/tree/candidate/package); C1's own spec/review authority digests are unrelated and valid.
- Contradiction sweep confirmed: C9/C12 exact keys consistent post-`remediatedFailureIds`; digest binding is order-independent stable-JSON (field list updated); no-change/authorized-evolution arrays forced empty explicitly; a release retry after freeze invalidation always re-derives `remediatedFailureIds` fresh (stale-freeze-exit-2 already prevents reuse); task DAG re-scanned globally and pairwise with the one new read-only anchor/edge — no new violation; full plan-requirements-design-task-spec.json projection re-derived via the real parser with zero drift.

## Round 6 (fresh review R8, verdict FAIL: 3 Critical, 2 High) — invariant-level closures, not case patches

- **Critical — global ownership-contention scan must be anchorsByTask-derived, not boundary-declaration-limited.** D10/I7 already claimed a "global and pairwise" scan, but neither named the actual derivation source. A systematic re-scan built the target→writer map directly from the projected `anchorsByTask` (not from prose) and confirmed all 9 real cross-boundary same-target pairs in this feature are in fact covered by an existing dependency boundary (one-boundary-per-pair reuse) — but found that R6-01's own Scope text had mislabeled one pair, merging the distinct R0-01/R2-01 (`validator-grounding.test.js`) pair into the R1-01/R2-01 (`validate-spec-output.cjs`) pair. This is exactly the failure mode a declaration-driven (rather than anchor-derived) scan cannot catch. Closed: D10/I7 now require the scan to derive candidates from the complete anchor set independent of declared boundaries; any single dependency boundary between a pair covers every target they share; R1-01 (sole write-owner of `validate-spec-output.cjs`) implements this; R6-01 verifies only, and its Scope enumeration is corrected. New negative fixture: a synthetic pair named in no boundary at all must still fail exit 1.
- **Critical — `resolveFailure` must self-verify the published receipt, never trust a caller's digest/id claim.** The only check was a scalar digest match against a caller-supplied argument; `resolveFailure` never read the actual C12 receipt bytes or checked that the cited `failure_id` was a member of that receipt's own `resolvedFailureIds`. A caller could cite an unrelated open `framework_regression` failure alongside a correct digest and have it marked resolved. Closed by new **I13**: `advanceBaseline` durably persists the exact validated receipt bytes at `packages/spec/.cafekit-release/release-receipt.json` before its authority rename; `resolveFailure` independently re-reads those bytes, recomputes the digest, exact-matches it against the current authority, validates the exact schema, and requires `failure_id` membership before appending.
- **Critical — `authorized_evolution` must rebind to the latest accepted PASS; a legitimate post-PASS correction must never self-lock.** D11/I9 pinned every R2-01..R6-01 citation to "this exact seed PASS entry... never a different or later-superseding PASS." Since the seed entry's own digest is frozen, any legitimate post-seed requirements/design correction (including this very round's edits) would permanently orphan the citation — a real deadlock, and inconsistent with C1's own general rule for ordinary `authorized_evolution` use, which already allowed citing any lineage PASS with a matching current digest. Closed by new **I14**: citation always resolves to the highest-`sequence` PASS entry in the same lineage whose own digest matches current bytes (unambiguous, never a superseded/foreign/mismatched entry); a fresh re-PASS after any legitimate correction simply becomes the new latest entry. Distinct from C14's `bootstrapReviewDigest`, a one-time historical fact unaffected by this change.
- **High — C9 is the sole canonical field-list authority for `candidateDigest`; R1.5 had drifted.** Rounds 4–5 added `failureLedgerDigest`/`failureLedgerGeneration`/`remediatedFailureIds` to C9's binding in design.md, but requirements.md's R1.5 (and its spec.json projection) still listed only the original 7-field Round-1 set — an uncaught, live contradiction between two canonical documents. Corrected R1.5 to the full 10-field list and declared C9 canonical; a repo-wide sweep found no other stale copy (plan.md's Round-1 H2 entry is left as accurate dated history).
- **High — the legacy-bridge artifact needed an exact lifecycle owner.** It remains outside the current 10-task DAG as an L0 gate; D11 names the reviewer and dedicated lifecycle writer, while lifecycle-only R1-03 later owns generation-0 activation, not the bridge artifact.
- Contradiction sweep confirmed: C1/C9/C12/C15 chain still non-circular after I13/I14 (no new proposal-store field, no new C13 key); I11's crash/idempotency ordering unaffected (the new receipt-persistence sub-step is itself idempotent and strictly precedes the authority rename); task DAG re-derived via the real parser and globally re-scanned — same 9 pairs, no new boundary, no duplicate producer, no cycle; `ready_for_implementation` remains false and `semantic_review` remains `not-run`.

## Round 7 (self-caught crash/retry contradiction inside Round 6's own I11/I13/C12 fix, no new external review)

- **Critical — publication is three events (A/B/C), not two.** Round 6's I13 added a canonical-receipt-persistence write inside `advanceBaseline`, but I11's own definition still said "two independent single-file-atomic writes," and the crash-resume prose claimed a crash before the authority rename "leaves nothing written" — false, since the new receipt-persist sub-step already ran first. The Round 6 contradiction sweep explicitly (and wrongly) called this "merely additive." Closed by re-modeling release publication as exactly three ordered, independently idempotent single-file events: (A) persist the canonical C12 receipt, (B) rotate the C10 authority (the sole publication checkpoint), (C) append the C15 `resolved` event per id. Every crash point now has an exact, named residual (nothing / staged-unpublished-receipt / rotated-authority-pending-resolve) instead of a blanket, sometimes-false claim.
- **Critical — the idempotency short-circuit must verify, and can idempotently repair, canonical receipt evidence instead of trusting a bare digest match.** If a crash, disk fault, or tamper destroyed or corrupted the persisted receipt file *after* a successful publish, a retried `advanceBaseline` would see the digest already matched and return success without ever checking the file `resolveFailure` (I13) depends on — a reachable, self-inflicted deadlock (advanceBaseline reports success; resolveFailure has nothing to read). Closed by hardening the short-circuit into three branches: evidence-intact success; evidence-missing-but-supplied-bytes-proven repair (re-persist the same cryptographically verified bytes, re-verify, then success — recovery, not a new publish, no freeze/candidate re-check needed); and supplied-bytes-invalid exit 2 (never reconstruct or guess).
- **High — path authority.** I13's original "explicit `receiptPath` argument... used only by owned tests" wording described a real parameter on the production signature with only a soft convention limiting its use. Corrected: production `advanceBaseline`/`resolveFailure` resolve the canonical path from a fixed trusted root only, with no per-call caller-supplied alternate; tests bind an isolated trusted root only at module/harness construction time, containment verified once.
- Contradiction sweep: I12 (remediatedFailureIds/resolvedFailureIds equality) and I14 (latest-accepted-PASS) are untouched by this round — neither depends on which of the three publication events has run, only on the receipt's field values, which are unchanged. The R8-C1 (global ownership scan) and R8-H2 (legacy-bridge L0 gate) closures from Round 6 are likewise untouched. No task, anchor, boundary, or DAG edge changed.

## Resolved Governance Decisions

- Non-inferiority is exact: zero additional hard failures and candidate aggregate quality greater than or equal to the frozen baseline; equality passes and no margin weakens either rule.
- Sealed generation rotates every RC, never feeds tuning, and remains external for two completed releases before a retired case may enter public regression.
