# Requirements

## Outcomes

- CafeKit promotes `ready_for_implementation` only after explicit semantic PASS with zero unresolved blockers on frozen C2, with repair_round as the C13 `attempt_index` (0/1/2 = first/second/third attempt of the current PASS-closed `review_epoch`, FAIL at 2 blocks a fourth attempt of that epoch) derived from a durable, append-only, whole-lineage-deduplicated `semantic_review_history`, and lifecycle disposition separate from reviewer verdict.
- Framework hotspot edits fail closed via tracked baseline authority whose empty-protected-path validity is conditioned on bootstrap-vs-released state (never a blanket HEAD-equality rule), self-derived paths that exclude both reserved control-plane files (release-baseline.json and benchmark-failure-ledger.json) before derivation, C9 freeze digests bound to both authority and C15 ledger digest+generation, an exact C14 `BootstrapAttestation` grounding the trust root (no `treeDigest` field, `bootstrapReviewDigest` bound to the fresh post-cutover seed PASS, never a merge-base guess), and reserved baseline transitions without lifecycle deadlock after advance.
- ChangeProposal C1 is a tagged change-intent (`benchmark_remediation` for framework-regression fixes, carrying `failure_ids` that must exactly match every intersecting open C15 ledger entry; `authorized_evolution` for legitimate feature/compatibility/security/maintenance change gated on a fresh spec and the latest accepted independent PASS in that spec's lineage whose own recorded `semantic_digest` equals the current one, I14) that never blanket-freezes legitimate development and is refused unconditionally, with no citation able to pass it through, whenever it intersects an open ledger entry; a legitimate post-PASS requirements/design correction never self-locks `authorized_evolution` — a fresh re-PASS simply becomes the new latest accepted entry in the same lineage; C1 never holds the release-candidate lifecycle binding digests (baselineAuthorityDigest, baselineCommit, treeDigest, candidateDigest, packageVersion, baselineGeneration) — freeze C9 is the sole binder of those — while `authorized_evolution`'s own `spec_semantic_digest` and `independent_pass_receipt_digest` remain valid C1 fields, not a contradiction of C9's role; advanceBaseline requires an exact C12 `ReleaseReceipt` whose digest is computed externally, whose `artifactDigest` is independently re-hashed from the real packaged `.tgz`, never embedded or merely declared, and whose `resolvedFailureIds` drives C15 `resolveFailure` only after `resolveFailure` independently re-reads and verifies the persisted receipt bytes and confirms the id's own membership in `resolvedFailureIds` (I13) — never trusting a caller-supplied digest or id claim.
- A durable C15 `BenchmarkFailureLedger` (an append-only event log of `opened`/`classified`/`reclassified`/`resolved` transitions, generation+digest-chain provenance identical to C10) is the sole record of open benchmark failures; R0-01 owns its schema, loader, and every named transition and is its sole file writer; R4-01 invokes `classifyFailure`/`reclassifyFailure` as a consumer after a fresh adjudication; R5-01 invokes `resolveFailure` as a consumer at release time; there is no bypass when the ledger is missing-when-required or malformed.
- Implementation under the legacy-bridge PASS is exempt on exactly R0-01, R1-01, R1-02 (build the bootstrap contracts only, never invoke `bootstrapBaseline`, never freeze/publish); a fresh, real, post-cutover semantic review must PASS first (`semantic_review_history` sequence 0/review_epoch 0) before `bootstrapBaseline` activates live authority, after which R2-01..R6-01 implement through the live choke via `authorized_evolution` bound to the latest accepted PASS in that same lineage (ordinarily this seed entry, I14); the final freeze/receipt/advance never runs until every task has landed and every gate has passed — no partial R0/R1 publish (D11/I9). The legacy-bridge artifact itself is a pre-implementation L0 gate, not a task-graph member: a fresh independent reviewer produces the PASS evidence, a dedicated lifecycle worker is its sole writer strictly before any R0-01 edit, and R0-01's owned tests assert its exact schema as a machine-checkable precondition.
- C10 authority provenance is exact (`previousBaselineDigest` sourced from a real predecessor, never self-declared), with an explicit honest-agent-only threat model; C15's ledger provenance follows the identical rule.
- Dual-run IR uses complete C11 normalize/equality, one exact ASCII ordinal comparator (not locale-dependent sort), and mode authority with an exact promote-transition gate list and non-sticky rollback; orphan modules do not satisfy wiring.
- Ownership contention is checked globally and pairwise across every coordination boundary, not only within one boundary (I7); the candidate pairs are always derived from the complete `anchorsByTask` write-anchor projection, never limited to whatever boundaries were declared — an entirely omitted boundary for a real same-target pair is caught, not tolerated. `validate-spec-output.cjs`'s sole write-owner R1-01 implements this scan; R6-01 is a read-only consumer that owns only the negative-fixture proof.
- Semantic-firewall dedicated tests are required via existing aggregate runner; public 8 fixtures have field-level schema; private/sealed external; B1 unshipped as a settled source-only release-governance scope decision (D9).
- No implementation while ready=false; legacy bridge after independent PASS only, bounded to the exact boot-window above.
- A required authoring stage becomes `validated` only via a current-run validator-plus-grounder pass over its own exact bytes, strictly before the semantic reviewer computes any digest that claims to cover it (R3.7), with that freshness proven by a durable per-stage digest receipt (C16, R3.8) rather than the `draft|validated` enum alone; the legacy-bridge lifecycle worker preflights every finalizer-required condition on an unpersisted candidate before writing the staged bridge artifact, which remains unconsumed until the finalizer's own atomic `ready_for_implementation=true` promotion, with rollback/quarantine — never in-place edit or cross-digest reuse — on any finalizer failure short of that promotion (R1.14).
- A new C16 `AuthoringValidationReceipt` at `validation.authoring_validation` durably binds an exact raw-byte digest for `requirements.md` and `design.md`, a raw-byte digest for `research.md` or the exact sentinel `RESEARCH_ABSENT_DIGEST` when absent, and an ASCII-sorted-path stable-JSON task-bundle digest or the exact sentinel `TASKS_ABSENT_DIGEST` when taskless (R3.8), computed only from those authored bytes — never from `semantic_digest` or the receipt's own bytes, so no circular digest is possible. `spec-authoring-validation.cjs` is the sole atomic writer of any `authoring.*` transition to `validated` together with this receipt: it builds an in-memory candidate, invokes the canonical validator and grounder over that exact candidate, and atomically replaces spec.json only on a fully clean pass, all-or-nothing — a failed or partial run leaves spec.json completely unchanged (D13, R3.9). Every consumer (the validator, the finalizer, and `authorized_evolution`'s C1 check) treats an `authoring.<field> = validated` reading as equivalent to `draft` whenever this receipt is absent or its stored digest for that field diverges from a freshly recomputed digest over the field's current bytes — the enum alone is never sufficient proof of freshness (I20); no other writer (`spec-scaffold.cjs`, the semantic reviewer, the finalizer, or a hand-edit) may ever set a stage to `validated` or write this receipt (I21).
- Every verification/L0-gate command runs from this source checkout's own canonical `packages/spec/src/claude/scripts/`/`packages/spec/scripts/` entrypoints, never a self-installed or hand-copied `.claude/`/`.codex/` consumer projection.
- A misclassified C15 ledger entry is corrected only by a fresh, append-only, provenanced `reclassifyFailure` event — never an in-place rewrite — and a correction can never silently and permanently open a release path that a real, unaddressed `framework_regression` should still block (R1.9/R5.6).
- Every read-modify-write authority/ledger/freeze transition assumes a single-process, serialized caller; write-temp-then-rename gives single-write atomicity and crash-safety only, never protection against two genuinely concurrent invocations racing on the same file — concurrent invocation is out of scope and must be serialized by the caller.

## Scope

### In scope

- Discriminated-union release-baseline authority, an exact C14 BootstrapAttestation trust root (no treeDigest, seed-PASS-bound bootstrapReviewDigest), and named bootstrap/advance transitions with exact predecessor provenance.
- Non-self-referential freeze with authority digest+generation binding, C15 ledger digest+generation binding, and post-advance invalidation.
- D1 sole normative protected allowlist and two reserved control-plane paths (release-baseline.json under C10, benchmark-failure-ledger.json under C15).
- Tagged C1 change-intent (benchmark_remediation with required failure_ids, authorized_evolution with no failure_ids, no ledger-intersection bypass, and a rebind-to-latest-accepted-PASS rule that never self-locks after a legitimate post-PASS correction, I14) that gates unproven change without freezing legitimate evolution; C9 separation; candidate digest non-circular and its exact field set canonically owned by C9 alone.
- C15 durable BenchmarkFailureLedger (opened/classified/resolved events); R0-01 sole schema/loader/transition owner and file writer; R4-01 classify-consumer; R5-01 resolve-consumer; no bypass on missing/malformed ledger; `resolveFailure` independently re-reads and verifies the canonically persisted C12 receipt bytes and `failure_id` membership before appending, never trusting a caller-supplied digest or claim (I13).
- A one-time, exact boot-window (D11/I9): legacy-bridge PASS exempts only R0-01/R1-01/R1-02 to build (never invoke) bootstrap contracts; a fresh post-cutover PASS seeds history; lifecycle-only R1-03 invokes bootstrap and persists generation-0 activation authority; R2/R3/R4 require that receipt. The bridge artifact remains an L0 gate outside the 10-task DAG and no partial R0/R1 publish is allowed.
- C2 receipt with verdict vs lifecycle_disposition; C13 durable append-only, whole-lineage-deduped semantic_review_history with review_epoch; finalizer-derived, epoch-scoped repair_round attempt index.
- C16 durable per-stage `AuthoringValidationReceipt` and the single atomic `spec-authoring-validation.cjs` coordinator that is the sole writer of any authoring-stage `validated` transition together with the receipt; every consumer (validator, finalizer, `authorized_evolution`) applies the same digest-based freshness check instead of trusting the enum alone.
- C11 dual-run contract with one exact ASCII ordinal comparator and an exact promote-transition gate list with non-sticky rollback; kernel/lens ban unconditional wire.
- Public fixture field schema PR-01..08; adjudicator isolation; metamorphic/mutation.
- Release gates, packed parity, globally pairwise-checked ownership write_sets, semantic-firewall test discovery; C12 ReleaseReceipt exact contract (including resolvedFailureIds) with verified artifact bytes for advanceBaseline; no-partial-publish gate spanning every task.

### Non-goals

- Private/sealed bodies, oracles, credentials in-repo.
- CI beyond prepack/prepublishOnly.
- Fake PASS or coding while ready=false.
- Grok as release-blocking acceptance.
- Unrelated package version bumps.
- Case-ID/prompt-hash/domain expected constants as product fixes.

## Requirements

### Requirement 1: Change firewall real choke

#### Acceptance Criteria

- **R1.1** When any path under the D1 sole normative protected allowlist is proposed for edit, the change-firewall gate shall require the C1 discriminated union. `benchmark_remediation` alone shall require `primary_failure_class`, `invariant_id`, `hypothesis`, `owner_layer`, `evidence`, `true_positive_family`, `negative_control_family`, `rollback_condition`, and non-empty C15 `failure_ids`; `authorized_evolution` alone shall require `spec_ref`, `spec_semantic_digest`, `independent_pass_receipt_digest`, `planned_write_set`, `negative_control_family`, and `rollback_condition`, and shall forbid every remediation-only field including `primary_failure_class` and `failure_ids`. Unknown or cross-variant fields fail closed. Neither variant shall embed treeDigest, baselineCommit, packageVersion, candidateDigest, baselineAuthorityDigest, or baselineGeneration.
- **R1.2** When `change_intent = benchmark_remediation` and the primary failure class is not `framework_regression`, the gate shall refuse that proposal. This refusal applies only within the `benchmark_remediation` branch; it shall not block a distinct, valid `authorized_evolution` proposal for a legitimate change to the same or another protected path (see R1.7), and the gate shall never treat every product change to a protected path as automatically blocked.
- **R1.3** Freeze and release-preflight shall load baseline authority only from tracked `packages/spec/benchmarks/release-baseline.json` and shall reject any CLI, environment, or caller base override with exit code 2. The environment channel is a closed, exactly-enumerated boundary, never an open-ended name-shape guess over `process.env`: the gate shall reject presence (checked by exact key name via `Object.prototype.hasOwnProperty`, never by value, and never logged) of exactly these six reserved keys — `CAFEKIT_BASE_COMMIT`, `CAFEKIT_BASELINE_COMMIT`, `CAFEKIT_BASE_REF`, `CAFEKIT_BASELINE_REF`, `CAFEKIT_BASE_PATH`, `CAFEKIT_BASELINE_PATH` — and no other environment variable name, however base/baseline-shaped, is ever inspected, pattern-matched, or treated as an override attempt. An environment key this runtime never reads cannot influence baseline authority and is not an override channel by definition; a name merely shaped like `*BASE*`/`*BASELINE*` (including a third-party ambient var such as `GITHUB_BASE_REF`, or an unrecognized name such as `OVERRIDE_BASE_COMMIT`) is never a supported channel and must never be read as one. `deriveProtectedChangedPaths` shall exclude the reserved `release-baseline.json` path before computing the working-tree diff against authority baselineCommit, then self-derive protected changed paths under the D1 allowlist, excluding `packages/spec/.cafekit-release/**`; reserved-path exclusion takes precedence over the generic `packages/spec/benchmarks/` prefix match. Callers shall not supply empty changedPaths that replaces derivation. Validity of empty derived protected paths depends on authority `state`, not on `baselineCommit == HEAD` alone: when `state = bootstrap`, empty derived protected paths always exit 2 — bootstrap requires a real independent-PASS digest over a non-empty change set; when `state = released`, empty derived protected paths are always valid, including when `baselineCommit == HEAD`, and this is the normal clean-pack path. There is no blanket rule that exits 2 solely on `baselineCommit == HEAD` with empty paths regardless of authority state. baselineCommit shall be a git ancestor of HEAD or equal HEAD. Authority uses C10 discriminated union bootstrap vs released. Named reserved transitions bootstrapBaseline and advanceBaseline are the only writers of release-baseline.json; arbitrary out-of-band edits of that file still fail loadBaselineAuthority/assertBaselineUsable and exit 2, even though the path is excluded from C1 derivation. advanceBaseline runs only after a valid C12 release receipt matching the current freeze and candidate, atomically rotates authority, and invalidates freeze so no valid freeze remains until a new freeze. Freeze shall bind baselineAuthorityDigest and baselineGeneration so authority change invalidates prior freeze. `previousBaselineDigest` in a released-state record shall be sourced from the authority record's own bytes as `loadBaselineAuthority` actually returned immediately before the write — never caller-supplied or self-declared in the same write. `loadBaselineAuthority` shall apply exact load rules for: an absent first record (only bootstrapBaseline may create it; every other command exits 2); an uncommitted named bootstrap/advance write (trusted as current authority without requiring a prior git commit); a committed tracked record (read normally); and an out-of-band edit (detected via a generation/digest chain that cannot be reproduced from any valid transition input, exit 2 on next use). This provenance check is honest-agent tamper detection (accidental edits, buggy scripts, third parties without commit access) — it does not defend against a hostile actor already holding legitimate commit/push authority on the same account.
- **R1.4** Mutable freeze state shall live only at `packages/spec/.cafekit-release/change-firewall-freeze.json`, outside D1 allowlist, tree-digest inputs, and npm package files; callers shall not override that path. R0 shall own gitignore of `.cafekit-release/`. Freeze shall compute digests then write. Verification shall exclude freeze state from derivation. Release-preflight and prepack/prepublishOnly shall always require a valid freeze matching current authority generation and digest, and exit 2 when missing, malformed, or stale after advance, including when protected paths are empty. Empty protected paths are valid only when authority state is released, and in that case require changeKind `no_protected_change` and NO_CHANGE_ATTESTATION_DIGEST; empty protected paths during bootstrap state are never valid (see R1.3). Non-empty paths require a C1 proposal covering exact derived paths; C9 alone holds digest bindings.
- **R1.5** computeProtectedTreeDigest shall hash sorted paths with type, mode, and content or delete sentinel. proposalDigest shall hash C1 proposal bytes or equal NO_CHANGE_ATTESTATION_DIGEST. candidateDigest shall bind exactly the field set design contract C9 defines — **C9 is the sole canonical, exact field-list authority for this binding; this criterion mirrors it and must never drift from it** — currently baselineAuthorityDigest, baselineGeneration, baselineCommit, failureLedgerDigest, failureLedgerGeneration, remediatedFailureIds, changedPaths, treeDigest, proposalDigest, and packageVersion, without including candidateDigest in its own input. Freeze creates; release/prepack only verify and never self-heal.
- **R1.6** Real callers shall be freeze create, release-preflight, prepack, and prepublishOnly. R0 shall surgically wire package.json scripts while preserving the existing version field value. R0 shall own semantic-firewall test discovery in run-skill-self-tests with `--require-semantic-test`; aggregate test runs all discovered `*.semantic-firewall.test.js`. R0 verification requires only R0 basenames and a deliberately failing sentinel nonzero when injected.
- **R1.7** When a ChangeProposal declares `change_intent = authorized_evolution` for a legitimate feature, compatibility, security, or maintenance change to a D1 protected path, the gate shall accept it only when: the spec at the declared `spec_ref` has its own `workflow_policy.planning_depth` — the real durable-spec field — equal to `Compact` or `Full` (never `None`); separately, as its own distinct lifecycle-state check and never as a stand-in for `planning_depth`, that spec's `authoring.requirements` and `authoring.design` both equal `validated` **and** are fresh per C16 — that spec's `validation.authoring_validation` receipt is present and its stored `requirements`/`design` digests exactly equal digests freshly recomputed over `spec_ref`'s current `requirements.md`/`design.md` bytes (a `validated` reading with no matching fresh receipt digest is treated identically to `draft` and fails this check, I20); `spec_semantic_digest` equals that spec's current semantic_model digest (fresh, not stale); `independent_pass_receipt_digest` equals the **latest accepted PASS** in that spec's `semantic_review_history` lineage (I14) — the entry with `verdict = PASS` and the numerically highest `sequence` among all entries whose own stored `semantic_digest` field also equals that same current digest — never a lower-sequence match when a higher-sequence matching entry exists in the same lineage (a superseded citation), never an entry from a different spec or `lineage_id`, and never a digest-mismatched entry regardless of its own sequence; `planned_write_set` is the exact sorted-set match of the derived protected changedPaths; and `rollback_condition` plus `negative_control_family` are present. This rebinding rule means a legitimate post-PASS requirements/design correction never self-locks `authorized_evolution`: the superseded entry simply stops matching, and a fresh re-PASS at a higher `sequence` in the same lineage immediately becomes the new latest accepted PASS every subsequent proposal cites. The gate shall refuse `authorized_evolution` unconditionally, with no citation or field able to pass it through, whenever the derived paths resolve to a currently open (unclassified or classified `framework_regression`, unresolved) C15 ledger entry; `authorized_evolution` carries no `failure_ids` field and is never accepted merely because a proposal cites one — such a change shall use `benchmark_remediation` instead, citing the exact `failure_ids`. Rejecting a non-`framework_regression` class inside `benchmark_remediation` (R1.2) shall not be read as a blanket refusal of every legitimate product change to a protected path.
- **R1.8** `bootstrapBaseline` shall accept only a C14 `BootstrapAttestation` with an exact `baseCommit` that equals the `bootWindowBaseCommit` field durably captured in the legacy-bridge artifact (`specs/cafekit-semantic-eval-firewall/reports/bootstrap-legacy-bridge-review.json`, see D11) at the moment of the legacy-bridge ceremony — a fact recorded once, before any boot-window code landed, never later reconstructed from git history or a merge-base guess — and that is also a real git commit object and an ancestor of or equal to an exact `headCommit` that equals the actual current HEAD at run time, plus a `bootstrapReviewDigest` bound to the seed `semantic_review_history` entry's `review_receipt_digest` (the fresh, real, post-C2/C13-cutover PASS at sequence 0/review_epoch 0 — see R1.9/D11/I9; never the disposable legacy 2-key bridge report). C14 has no `treeDigest` field; `bootstrapBaseline` independently re-derives the protected tree digest at `baseCommit` itself rather than trusting a caller-attested copy, since `baseCommit` already pins the tree. Protected paths for the bootstrap change-set shall be self-derived from the `baseCommit`..`headCommit` diff under D1 (spanning the exact full boot-window diff); the caller shall not supply `changedPaths` directly. `bootstrapBaseline` shall refuse to run before the seed `semantic_review_history` entry exists, and shall write generation 0 with `baselineCommit = baseCommit` explicitly. There shall be no implicit `origin/main`, empty-tree base, or merge-base guess, and no caller base override outside this one-time attested bootstrap; every subsequent routine freeze shall read only the authority record.
- **R1.9** The change-firewall shall own a durable C15 `BenchmarkFailureLedger` at `packages/spec/benchmarks/benchmark-failure-ledger.json` with an adjacent exact schema, exporting `loadFailureLedger`, `assertFailureLedgerUsable`, `openFailure`, `classifyFailure`, `reclassifyFailure`, `resolveFailure`, `computeFailureLedgerDigest`, `deriveFailureState`, and `NO_FAILURES_ATTESTATION_DIGEST`; this file shall be a reserved control-plane path excluded from generic C1 diff derivation before the `packages/spec/benchmarks/` prefix match, exactly like `release-baseline.json`, and R0-01 shall be its sole file-write anchor. `openFailure` shall append an `opened` event with a unique `failure_id`, sorted exact `paths`, `candidate_digest`, `evidence_digest`, and `occurred_at`; `classifyFailure` shall append a `classified` event with `primary_failure_class` and a fresh C5 `adjudication_digest` only for a `failure_id` with an `opened` event and no prior `classified` event; `reclassifyFailure` shall append a `reclassified` event only for a `failure_id` with a prior `classified` (or `reclassified`) event and no prior `resolved` event, requiring an exact `previous_primary_failure_class` match against that `failure_id`'s currently-derived class and a fresh, non-reused C5 `adjudication_digest`, refusing (exit 2, no write) a stale/mismatched `previous_primary_failure_class`, a reused `adjudication_digest`, or any `failure_id` already `resolved`; `resolveFailure` shall append a `resolved` event with `decision_digest` and `release_receipt_digest` only for a `failure_id` classified `framework_regression` with no prior `resolved` event. `deriveFailureState` shall fold events, using the most recent classification-type event (`classified` or `reclassified`) to determine current class, so an entry is blocking while `opened`-only or classified `framework_regression` and unresolved, and nonblocking once classified as any other class or once resolved — a correction back to `framework_regression` immediately re-blocks the entry, and a correction away from it still requires the same fresh-adjudication proof, so no classification change can silently open or permanently close a release path. `assertHotspotChangeAllowed` shall refuse `authorized_evolution` unconditionally when derived paths intersect a blocking ledger entry, and shall accept `benchmark_remediation` only when its `failure_ids` exactly names every intersecting blocking entry and their combined `opened.paths` union equals the proposal's `paths` exactly. `loadFailureLedger`/`assertFailureLedgerUsable` shall fail closed (exit 2) on a missing-when-required, malformed, or provenance-broken ledger for every caller and every `change_intent`, with no bypass; a ledger that has never had `openFailure` called is the legitimate zero-failures state, not malformed.
- **R1.10** `createFreezeManifest` and `verifyFreezeManifest` shall always load the C15 ledger and bind `failureLedgerDigest` (sha256 of the current ledger bytes, or `NO_FAILURES_ATTESTATION_DIGEST` when the ledger file does not exist) and `failureLedgerGeneration` (the ledger's own `generation`, or `null` when absent) into the freeze, and shall include both fields in `candidateDigest`'s stable binding. Any mismatch between the freeze's bound ledger digest/generation and the ledger's current digest/generation shall exit 2, exactly as an authority digest/generation mismatch does — any accepted C15 ledger event (of any current or future named type) recorded after a freeze was created makes that freeze stale and it must be recreated; this rule is stated generically over "any accepted event," never as an enumerated, recount-prone list of event type names, so a future C15 transition never requires a matching update here.
- **R1.11** Publishing a release shall be exactly **three** independent single-file-atomic persistence events, never two, in this fixed order, never reordered or run concurrently, and never described or treated as one cross-file transaction: (A) `advanceBaseline` shall persist the canonical C12 receipt bytes at `packages/spec/.cafekit-release/release-receipt.json`; (B) `advanceBaseline` shall then rotate the C10 authority (`release-baseline.json`) — the sole publication checkpoint; (C) `resolveFailure` shall append a C15 `resolved` event to `benchmark-failure-ledger.json`, once per `resolvedFailureIds` id, invoked separately and strictly after `advanceBaseline` returns success. `advanceBaseline` shall check, before any other read or write, whether the current C10 authority's `releaseReceiptDigest` already equals the supplied receipt's own computed digest. When it does, `advanceBaseline` shall **not** return success on that digest match alone: it shall verify that the canonical persisted receipt exists, conforms to the exact C12 schema, and its own recomputed digest equals the published one, and only then return success without touching the freeze, candidate, or ledger; when the canonical file is missing or fails this verification but the supplied bytes for this call independently verify against the published digest and schema, `advanceBaseline` shall idempotently repair event (A) by re-persisting those exact supplied bytes at the canonical path, re-verify the write, and then return success — recovery of evidence for an already-published fact, never a new publication, requiring no re-validation of freeze/candidate state; when the supplied bytes themselves fail schema or digest verification, `advanceBaseline` shall exit 2 without writing and shall never reconstruct or guess receipt content. Otherwise (a genuinely new candidate), `advanceBaseline` shall perform every read-only validation, then event (A), then — strictly before event (B) ever runs — shall re-read the canonical persisted receipt bytes that write actually produced and verify an exact byte match (or, equivalently, a freshly recomputed digest plus exact C12 schema match) against the supplied receipt, exactly the same read-after-write verification the idempotent-repair branch above already performs on its own write; a mismatch (a physically corrupted write, a concurrent clobber, or a filesystem fault) shall exit 2 without ever running event (B), leaving the C10 authority exactly as it was and never returning `published`; only a verified event (A) shall be followed by event (B), and `advanceBaseline` shall never invoke `resolveFailure` itself. `resolveFailure` shall independently re-load the current C10 authority and refuse (exit 2, no write) unless that authority already shows the exact `release_receipt_digest` it is asked to append as published; it shall be idempotent per `failure_id` (a matching prior `resolved` event is a no-op; a mismatched one is refused, never coerced). A crash before event (A) shall leave nothing written; a crash after event (A) but before event (B) shall leave a staged, valid, unpublished receipt with the C10 authority and ledger unchanged — never described as "nothing written" — recoverable by re-invoking the same sequence; a crash after event (B) shall be recoverable by re-invoking `advanceBaseline` (its hardened idempotency check) followed by the `resolveFailure` loop, with no separate reconciliation command required and no partially-applied file write ever left inconsistent.
- **R1.12** `createFreezeManifest` shall set C9's `remediatedFailureIds` by copying the accepted C1 `benchmark_remediation.failure_ids` array exactly, and only after `assertHotspotChangeAllowed` has already proven the open-failure path-union invariant for those exact ids — never independently chosen, supplemented, or caller-supplied at freeze time. For `authorized_evolution` and for `changeKind = no_protected_change`, `remediatedFailureIds` shall always be the empty array. `remediatedFailureIds` shall be included in `candidateDigest`'s stable binding. `advanceBaseline` shall verify that C12's `resolvedFailureIds` is the exact sorted-unique-set equal of the current freeze's `remediatedFailureIds`, exiting 2 on any divergence, so a release receipt can never claim to resolve a failure that was not actually proven-remediated at gate/freeze time. `resolveFailure` shall only ever be invoked, per `resolvedFailureIds`, over ids that trace this exact chain (C1 gate proof → freeze binding → receipt equality → ledger resolution); no separate proposal store shall be introduced — C9 remains the sole durable vehicle carrying this gate-time proof forward to C12.
- **R1.13** `resolveFailure` shall never trust a caller-supplied `release_receipt_digest` or a caller's claim that a given `failure_id` belongs to the release being resolved. As event (A) of the three-event publication sequence (R1.11), strictly before event (B) (its authority rename), `advanceBaseline` shall durably persist the exact validated C12 receipt bytes at the canonical path `packages/spec/.cafekit-release/release-receipt.json`, resolved from a fixed trusted project/runtime root; production `advanceBaseline`/`resolveFailure` calls shall accept no per-call caller-supplied alternate path — an isolated trusted root may be bound only when constructing a test/harness instance of the module, with containment verified once at construction time. `resolveFailure` shall independently read those exact bytes, recompute `releaseReceiptDigest` over them, require an exact match against the current C10 authority's own published `releaseReceiptDigest`, validate the bytes conform to the exact C12 key set, and require the `failure_id` it is asked to append to be a member of that receipt's own `resolvedFailureIds` array — refusing (exit 2, no write) on any digest mismatch, schema violation, or absent membership, even when the current published digest is otherwise correct and even when the id names a real, currently open `framework_regression` ledger entry. When the canonical receipt evidence has been lost or corrupted after a prior successful publish, `advanceBaseline`'s own idempotency check (R1.11) shall repair it from cryptographically-proven-correct supplied bytes before `resolveFailure` is ever invoked again — `resolveFailure` itself never repairs, reconstructs, or guesses receipt content.
- **R1.14** The legacy-bridge artifact `specs/cafekit-semantic-eval-firewall/reports/bootstrap-legacy-bridge-review.json` is outside the current 10-task DAG and is never owned/written by a feature task. ### Requirement 3: Review receipt and readiness finalizer

#### Acceptance Criteria

- **R3.1** When a semantic review completes, `validation.semantic_review` shall use exactly the frozen C2 key set and types: status, semantic_digest, verdict, lifecycle_disposition, findings, unresolved_decisions, graph_coverage, repair_round, reviewed_criteria, counterexamples, and reviewer_evidence. Reviewer verdict is PASS or FAIL; lifecycle_disposition is CONTINUE or BLOCKED; these fields shall not be conflated.
- **R3.2** When structural validation and grounding succeed and the receipt verdict is explicit PASS with lifecycle_disposition CONTINUE, zero unresolved blocking findings or decisions, and derived repair_round in 0..2, the readiness finalizer shall be the only writer that may set `ready_for_implementation=true`.
- **R3.3** The finalizer shall derive `review_epoch` as the count of prior entries in the same `semantic_review_history` lineage whose `verdict` is PASS (epoch 0 before any PASS; a PASS entry is stamped with the epoch it closes; the next entry opens `review_epoch + 1` at `attempt_index 0`). repair_round shall be the C13 `attempt_index`: the count of prior entries in the **same `review_epoch`** whose `verdict` is FAIL — not the whole lineage's FAIL count. Index values 0, 1, 2 name the first, second, and third attempt of that epoch respectively. PASS at index 0, 1, or 2 may promote when all other gates pass, closing the epoch. FAIL at index 0 or 1 shall leave ready false and permit the next index of the same epoch. FAIL at index 2 (the third attempt of the epoch) shall set lifecycle_disposition BLOCKED, leave ready false, and block any fourth attempt of that epoch from ever occurring (index 3 never occurs within it, and a BLOCKED epoch is never reopened). Before deriving `review_epoch`/`attempt_index` for any new entry or appending it, the finalizer shall first check whether the latest entry already recorded for the current `review_epoch` in this lineage carries `lifecycle_disposition BLOCKED`; when it does, the finalizer shall refuse the entire operation outright — no `attempt_index` computed, no entry appended, no readiness decision changed — rather than silently deriving an out-of-range fourth-attempt index. The finalizer shall atomically append the current completed receipt to `semantic_review_history` together with the readiness decision; a receipt whose `review_receipt_digest` equals any existing entry's digest anywhere in the same lineage — not only the latest entry — is a replay, shall not be appended twice, and shall not increment `attempt_index` or `review_epoch`. Any caller-supplied `repair_round`, `review_epoch`, `semantic_review_history`, or `lineage_id` that diverges from the finalizer-derived state shall be rejected outright — this is the single rule, never a silent ignore. `lineage_id` shall remain stable across ordinary semantic authoring edits per I6; only spec recreation starts a new lineage. Missing or mistyped required fields, stale digest, or blocking unresolved items leave ready false and shall not invent PASS from counterexample shape alone.
- **R3.4** When the structural validator inspects a review receipt, it shall enforce C2 key set, types, nullability, enums, cardinality, stable ordering rules for digest inputs, and digest freshness only, and shall not judge semantic meaning.
- **R3.5** Automated tests owned by the finalizer task shall prove refuse paths for non-passing incomplete receipts and promote only for explicit PASS with CONTINUE and zero blockers, including at least one negative-control fixture, attempt-index derivation, and index-2 BLOCKED stop with ready false.
- **R3.6** When a semantic review completes, `validation.semantic_review_history` shall use exactly the C13 key set: `lineage_id` derived as sha256 of a stable-JSON object over the immutable fields `feature_name` and `created_at`, and `entries` as an append-only array whose items use exactly `sequence`, `semantic_digest`, `review_receipt_digest`, `verdict`, `lifecycle_disposition`, `blocking_count`, `attempt_index`, `review_epoch`. `review_receipt_digest` shall be the sole reference to the full receipt; findings, unresolved_decisions, and counterexamples shall not be duplicated into history. A receipt whose `review_receipt_digest` already matches any existing entry anywhere in the same lineage — not only the latest entry — is a replay and shall not be appended twice.
- **R3.7** A required authoring stage (`authoring.requirements`, `authoring.design`, and, when present, `authoring.research`/`authoring.tasks`) shall transition from `draft` to `validated` only as the direct, current-run output of `validate-spec-output.cjs` and `spec-ground.cjs` both completing cleanly over that stage's exact current bytes — never a manual flip, never inferred from a prior run, and never set by the semantic reviewer or the finalizer. The semantic reviewer shall compute `semantic_digest` (and every `graph_coverage`/counterexample claim it produces) only over bytes for which every required stage already shows `validated`; a receipt computed over stage bytes that are later marked `validated` without recomputing the digest is stale and shall not be treated as covering the validated state. Any edit to a stage's authored bytes after it was marked `validated` shall immediately revert that stage to `draft` until validator and grounder both re-confirm it over the new bytes; a `validated` flag left stale against since-changed bytes shall be treated identically to `draft` by every downstream consumer, including `authorized_evolution`'s C1 check (R1.7) and the finalizer's C13 lineage.
- **R3.8** `validation.authoring_validation` (C16 `AuthoringValidationReceipt`) shall be `null` until the first successful coordinator run and, once present, shall have exact keys `schema_version` fixed `"1"`, and `requirements`, `design`, `research`, `tasks` — each an object with exact keys `digest` and `validated_at` (ISO string). `digest` for `requirements`/`design` shall be a raw-byte sha256 (colon plus 64 lowercase hex) of that stage's exact current file bytes with no normalization. `digest` for `research` shall be the same raw-byte sha256 of `research.md` when `authoring.research != absent`, or the exact literal sentinel `RESEARCH_ABSENT_DIGEST` when absent. `digest` for `tasks` shall be a sha256 over the stable-JSON canonical bytes of an array of objects, each with exact keys `path` and `digest` — one object per task file, `path` the exact repo-relative path and `digest` the raw-byte sha256 of that task file — sorted by `path` using the same exact ASCII ordinal string comparator C11 defines (never `localeCompare`), or the exact literal sentinel `TASKS_ABSENT_DIGEST` when zero task files exist. None of these digests shall be computed from `semantic_digest`, `review_receipt_digest`, or the receipt's own bytes — no circular digest is possible. A stage is fresh if and only if `authoring.<field> = validated` and the receipt is present and its stored digest for that field exactly equals a digest freshly recomputed, at read time, over that field's exact current bytes by this same algorithm; every other case (`authoring.<field> = validated` with the receipt absent, with no entry for that field, or with a digest mismatch) shall be read as `draft` by every downstream consumer — `validate-spec-output.cjs`, the finalizer, `authorized_evolution`'s C1 check, and `spec-scaffold.cjs` alike (I20).
- **R3.9** `packages/spec/src/claude/scripts/spec-authoring-validation.cjs` shall be the sole writer of any `authoring.requirements`/`authoring.design`/`authoring.research`/`authoring.tasks` transition to `validated` and of `validation.authoring_validation`. It shall construct an in-memory candidate spec.json (never persisted until success), invoke the canonical `validate-spec-output.cjs` and `spec-ground.cjs` against that exact candidate's current bytes, compute the R3.8 digests, and only on every check completing cleanly shall it atomically replace spec.json (write-temp-then-rename) with the updated `authoring.*` enum values and the fresh C16 receipt written together in the same replace. Any failure, partial check, or exception shall leave spec.json completely unchanged — no partial persisted state. No other writer — `spec-scaffold.cjs`, the semantic reviewer, the finalizer, or a hand-edit — shall ever set an authoring stage to `validated` or write this receipt (I21); `spec-scaffold.cjs` shall write only `draft` or `absent` for these fields, never `validated`, removing any prior asymmetric preserve-on-migrate behavior for `requirements`/`design`.
