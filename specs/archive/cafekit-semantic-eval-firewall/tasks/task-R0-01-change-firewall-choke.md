# Task R0-01: Change firewall real choke
**Status:** in_progress

## Outcome

Land the production change-firewall with D1 sole allowlist (two reserved control-plane paths), C10 discriminated baseline authority with exact predecessor provenance and named reserved transitions, a one-time C14 BootstrapAttestation trust root (no treeDigest field, no merge-base guess, bootstrapReviewDigest bound to the fresh seed PASS), a durable C15 BenchmarkFailureLedger with its own generation+digest-chain provenance and named transitions, non-self-referential freeze binding authority digest+generation plus C15 ledger digest+generation, a tagged C1 change-intent (benchmark_remediation requiring failure_ids, authorized_evolution with no failure_ids, no ledger-intersection bypass, and a rebind-to-latest-accepted-PASS rule that never self-locks, I14) that gates unproven change without freezing legitimate evolution, C9 sole digest binder without circular digests, `resolveFailure`'s independent self-verification of the persisted receipt bytes and failure_id membership (I13), the legacy-bridge artifact's precondition check as a machine-checkable, non-DAG L0 gate (D11), the shared `spec-authoring-digest.cjs` C16 freshness primitive that `authorized_evolution` uses instead of trusting the authoring enum alone (D13), package prepack wiring preserving version, and R0-only semantic-firewall tests with discovery require flags. R0-01 builds these bootstrap contracts under the legacy bridge but does not invoke `bootstrapBaseline`, create a real freeze, or publish (D11/I9 boot-window).

## Scope

- **In scope:** change-firewall module; append-only C10 baseline-envelope schema, provenance rule, and bootstrap writer; C14 bootstrap-attestation schema (no treeDigest); bootstrap-activation receipt schema and its dedicated test for lifecycle-only R1-03; C15 benchmark-failure-ledger schema, loader, and named transitions (openFailure/classifyFailure/reclassifyFailure/resolveFailure); freeze schema/state + gitignore (binds ledger digest+generation); tagged C1 proposal schema (benchmark_remediation with failure_ids, authorized_evolution); migration manifest; release-preflight; freeze wire; `advanceBaseline`'s receipt-bytes persistence and `resolveFailure`'s independent self-verification (I13); the legacy-bridge artifact's precondition assertion (read-only, R0-01 never writes it, D11); the shared `spec-authoring-digest.cjs` freshness primitive (C16 digest algorithm, D13) and `authorized_evolution`'s use of it against `spec_ref`'s own receipt instead of trusting the `validated` enum alone; package.json scripts preserving version; discovery + run-skill-self-tests; R0 dedicated tests; reserved transition writers for release-baseline.json and benchmark-failure-ledger.json.
- **Out of scope:** C2 cutover, finalizer promote, IR dual-run, future-task basenames, version bumps, generic proposal for authority rotation, C12 artifactDigest re-hash wiring (R5-01 owns invoking it inside benchmark-workflow.mjs's release path), invoking `bootstrapBaseline` itself (deferred until the fresh post-cutover seed PASS exists per D11/I9 — R0-01 delivers the function, not its invocation).

## Acceptance

- **R1.1:** Tagged C1 accepted per its own variant rules; `benchmark_remediation` semantic-only fields (including `failure_ids`) accepted for framework_regression path covers.
- **R1.2:** Non-framework_regression classes never accept hotspot paths inside `benchmark_remediation`; this never blocks a distinct valid `authorized_evolution` proposal.
- **R1.3:** No baseline lifecycle deadlock; complete append-only envelope replays from genesis to tail; empty-path validity conditioned on bootstrap-vs-released tail state, not blanket HEAD equality; advance invalidates freeze; reserved transitions only; reserved-path exclusion precedes derivation; every `previousBaselineDigest` is recomputed from the exact preceding in-envelope record.
- **R1.4:** Freeze always required; no_protected_change attestation valid only in released state; post-advance stale fails; out-of-band release-baseline.json edits fail closed.
- **R1.5:** Digests non-circular on C9 sole binder.
- **R1.6:** R0 basenames required; version preserved; sentinel nonzero.
- **R1.7:** `authorized_evolution` accepted only under its exact real-field (workflow_policy.planning_depth + validated-and-C16-fresh authoring, via the shared `spec-authoring-digest.cjs` primitive this task builds)/latest-accepted-PASS (I14)/write-set/rollback rule; refused unconditionally (never via citation) whenever it intersects an open C15 ledger entry; a superseded (lower-sequence) matching-digest PASS is refused when a newer matching entry exists in the same lineage; a `validated` authoring enum with an absent or digest-mismatched C16 receipt is treated as `draft` and refused (I20).
- **R1.8:** Bootstrap accepted only via an exact C14 attestation (no treeDigest) whose baseCommit is verified equal to the legacy-bridge artifact's bootWindowBaseCommit and bound to the seed PASS entry; no implicit `origin/main`, empty tree, or merge-base guess; refuses to run before the seed PASS exists.
- **R1.9:** C15 ledger schema/loader/transitions exact and reserved; `authorized_evolution` never accepted via `failure_ids` (it has none); `benchmark_remediation` accepted only with an exact `failure_ids` match; no bypass on missing/malformed ledger; a misclassification is corrected only via an append-only, fresh-adjudicated `reclassifyFailure` event refused on a mismatched `previous_primary_failure_class`, a reused digest, or an already-resolved id, and `deriveFailureState` uses the most recent classification so a correction never silently and permanently opens a release path.
- **R1.10:** Freeze/candidateDigest bind ledger digest+generation; a ledger event since the last freeze makes it stale.
- **R1.11:** Publication is exactly three ordered, single-file-atomic, independently idempotent events (A persist receipt, B rotate authority, C resolve ledger); advanceBaseline's idempotency check verifies (and idempotently repairs, never blindly trusts) canonical receipt evidence before returning success; the same read-after-write verification runs symmetrically on the genuinely-new-candidate (first publish) branch immediately after event A's physical write and strictly before event B ever runs, so a physically corrupted or clobbered event A write throws fail-closed with authority left exactly unrotated and never reported published; a crash after A before B leaves a staged unpublished receipt, not "nothing written"; a crash after B resolves correctly on retry with no reconciliation command and no faked cross-file transaction.
- **R1.12:** remediatedFailureIds copied exactly from a gate-proven benchmark_remediation, empty for authorized_evolution/no_protected_change, bound into candidateDigest; advanceBaseline refuses any resolvedFailureIds divergence from it.
- **R1.13:** resolveFailure independently re-reads (from a fixed trusted path, never a per-call caller path) and recomputes the digest over the canonically persisted receipt bytes (never trusting a caller-supplied digest), validates the exact C12 schema, and refuses any failure_id absent from the receipt's own resolvedFailureIds even with a correct current digest; a lost/corrupted canonical file after a prior publish is repaired by advanceBaseline from proven-correct supplied bytes, never by resolveFailure itself.
- **R1.14:** The legacy-bridge artifact's exact schema is asserted as a machine-checkable precondition by R0-01's owned tests before any other R0-01 assertion runs; R0-01 never writes, preflights, or quarantines this artifact — that lifecycle (green preflight before write, staged until the finalizer's atomic SPEC_READY promotion, quarantine on finalizer failure) belongs to the L0-gate lifecycle worker per D11/I16, outside this task.
