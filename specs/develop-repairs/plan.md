# Develop repairs — fix what the measurement exposed
Specs-Contract: process-first-ready-v1

## Scope decision (GATE-SCOPE — 2026-09-22)
- Chosen: **both groups**. Repair the four skill-text defects found by evaluating `cf:develop` against thirteen real tasks, plus the two contract defects found by running the gate, and then **re-measure with `evals/develop`**. The user chose the widest option at the gate and the full re-measurement.
- Ships inside **0.16.8**, which is committed and pushed but not yet published, so its changelog entry is extended rather than a new version opened.
- Expansion signals: four source files and one script, one deliverable group, no new service — below the split threshold, so one packet.

## What scouting changed about the scope
The gate group is smaller and safer than it looked at GATE-SCOPE, and the plan records why rather than quietly shrinking:
- **`final-Head fixed point` is prose only.** It exists at `develop/references/quality-gate.md:75-89` and **no script implements it** — a search across `packages/spec/src` and `scripts` finds it in `run-skill-self-tests.mjs`, `develop/SKILL.md` and `quality-gate.md`, and in no `.cjs`. The machine's `provenance` check only requires the Receipt's Base/Head to match the runtime; it never demands a re-run, so the prose is **stricter than the machine it describes**. The conclusion that this makes it free to edit was wrong: the probe suite pins five of that section's clauses verbatim and one anchor byte-exactly including where its line breaks, so the edit is cheap in blast radius and **expensive in precision**.
- **`command_identity` is real machine behaviour**, in `spec-receipt.cjs` (3 occurrences), and it is fail-closed: with no single `- Command:` line it returns the failure rather than skipping the check. This is the only change in this packet that alters what the gate accepts.
- Installed copies exist per project. Of three checked, only `radar-insight` carries `.claude/scripts/spec-receipt.cjs`; `keihi-pilot` and `WMS-SYSTEM` do not. A gate change reaches a project only when that project reinstalls, so no existing packet breaks the moment this ships.

## Why this is wanted
`cf:develop` was evaluated this morning against thirteen tasks executed today, and measured this afternoon with forty paid runs. Both produced defects with evidence, not opinion:
- One environment defect — a verification command that fails for a reason unrelated to the code — left the code correct in **20 of 20 runs** while the task closed in only **2 of 10** for sonnet (two-sided Fisher **p = 0.0055**). The skill has no step that would have caught it: its cycle is Scout, Implement, Verify, with nothing that checks the verification runs *before* the work starts.
- The Receipt-after-review ordering is stated once, mid-paragraph, at `develop/SKILL.md:140`; the controller violated it in `skill-routing` task 02 and had to reopen a closed task.
- The three-round repair cap at `SKILL.md:138` never defines a round. In `skill-routing` task 01 the controller could not tell whether it was on round 2 or 3.
- `### 1. Scout` lists entrypoints, callers, dependents, registration, errors and owned files, but not the probe or test that will judge the work. Two of task 01's four rounds were spent discovering pinned constraints a scout would have read.
- The two contract defects cost real money and real reopening: the prose fixed point pointed at an $11.77 measurement in `skill-routing`, and `command_identity` rejected a Receipt whose Verification Plan had been deliberately split into four commands to keep a cost checkpoint reachable.

## Measured constraints (2026-09-22, HEAD `ac337bc`)
- **There are two ceilings, and the second is the binding one.** `develop/SKILL.md` must stay within 140–200 lines (`run-skill-self-tests.mjs:5163-5165`) and it is at 178. But `:2516-2518` also caps four files together at **400**: `develop/SKILL.md` 178 + `develop/references/parallel-waves.md` 80 + `sync/SKILL.md` 79 + `sync/references/sync-protocols.md` 62 = **399**. The real headroom is **one line**, not twenty-two, and an earlier draft of this plan sized the work against the wrong ceiling.
- **The room exists, and was found by mapping the file rather than guessing.** Projecting every literal the probe suite shares with `develop/SKILL.md` onto its lines shows 47 such strings covering **68 of 179 lines**; the other **111 are free**. The question was never whether there is space, but which space is safe, and nobody had looked.
- **The one genuinely redundant passage is `### Flash (--flash)`, 15 lines.** `references/quality-gate.md:91-107` states the same rule more completely, including the record template the skill omits, and the skill already uses the short-pointer form for its sibling mode: `### Parallel` is four lines and says "Load `references/parallel-waves.md`". Flash is the only mode that copies its reference instead of pointing at it. Reducing it to the Parallel shape frees about ten lines, which is what the four additions need.
- Three literals in that file are pinned and must survive byte-for-byte: the loaded-sections sentence in `CONSUMER_SECTION_CLAUSES.developLoads` (`:1026`), the pair `--parallel` with `references/parallel-waves.md` (`:4371`), and `### 1. Scout` with `Trace entrypoints, callers, dependents` (`:4497`).
- `DEVELOP_PLAN_NATIVE_PATHS` (`:2349`) binds all four develop files into one contract checker, so a change in `quality-gate.md` is checked together with `SKILL.md`.
- The hook suite already exists: `packages/spec/src/claude/hooks/__tests__/spec-gate.test.js` holds 68 tests, which is where a `command_identity` change is proved.
- The full suite is 1366 tests and takes about ten minutes.
- `evals/develop/` exists from the packet closed an hour ago, so this is the **first skill repair in this repository that can be measured before and after**. The before figures are in `specs/develop-efficiency/task-03-measure-efficiency.md`.

| D-01 | Fix the prose fixed point rather than build machine enforcement for it | Implement it in a script; delete the rule | No script implements it today, so the cheapest correct move is to make the prose ask for what the machine already checks plus an artifact-hash escape | A Receipt that pins artifact hashes proves non-drift as well as a re-run does | An artifact-pinned Receipt is later found stale despite matching hashes → the escape is unsound and the rule returns to demanding a re-run |

## Known limitations carried into execution
- The after-measurement inherits both holes of the before-measurement: no grader runs the test, so a near-miss implementation counts as correct, and `Base`/`Head` are not genuinely derivable in the eval workspace, so the close being counted is weaker than the real gate. - The eval still runs `cf:develop` without hooks or the completion gate, so both sets of figures are floors for the skill text alone.
- A gate change reaches another project only when that project reinstalls. Projects on an older installed copy keep the old behaviour, which is safe here because the change only widens what is accepted.
- Ten runs per model separates 2/10 from 9/10 and does not settle a difference of one or two runs, so a small movement in the after-figures will not be readable.
