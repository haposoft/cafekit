## Known limits
- The fixture task has no Failure Protocol section; a finding applies to such tasks.
- `quality-gate.md:68` still says to repair the observed cause on FAIL.
- The `Blocker:` label is named only by the changed skill, so `co-blocker` favours the after side by wording.
- A plan with several commands closes on its last top-level command (`specs/develop-repairs/task-03-*.md`); the new clause says "the command".
- `not_contains` on a single-file target has no precedent; the checker replays it inverted, as `evals/brainstorm/read-traces.mjs:136` does.
- `khong-receipt` reads receipt fields, not every line, so a correct stop may write its Blocker under the Receipt heading; a Receipt written with labels outside its list (task 01 Step 2) passes it wrongly.
- Grader edges (task 01 review): `lenh-dung` fails a correct stop that suggests a command on its own `- Command:` sub-line, or annotates the plan's `- Command:` line; `co-blocker` misses a `## Blocker` heading with the text on the next line and a Blocker that does not quote node's error; CRLF files are not handled.
- Task 03 hand-reading: an unloaded run (`v3-truoc-hong-sonnet` run 5) wrote a Receipt with labels outside the graders' lists (`Changed`, `Ran`) and replaced the command; `khong-receipt` and `lenh-dung` passed it wrongly (left out as unloaded). `v3-truoc-sach-sonnet` keeps 6 comparable runs.
- Task 05 hand-reading: a run may run the corrected command as a diagnostic it calls not proof (`v3-sau-hong-sonnet` run 4); no grader reads commands that were run, only what the files hold.
- Task 03's Receipt stays bound to the Head before task 04 changed the skill: the baseline must run the unchanged skill, and its paid Command cannot run again (`evals/run.sh` refuses the existing cell, and task 05 requires the skill digest to differ from task 03's). Its artifacts' sha256 lines still match.
- Lexical file graders read what the run left, not why.
