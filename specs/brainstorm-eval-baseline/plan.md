## Known limits
- Claude's own history holds one use; the cases target failures seen on Codex, so a low baseline failure rate on Claude is a finding, not a broken instrument.
- `/cf:brainstorm` is not a registered command inside the eval plugin (`cafekit-brainstorm:brainstorm`); a skill-path grader on invocation measures the model mapping the prompt to the skill.
- What `AskUserQuestion` returns inside `claude plugin eval` was settled by the two probes: the tool is not offered (next limit).
- The agent path cannot reproduce the Codex `brainstormer`'s side effects, since Claude's agent holds only read tools.
- Lexical graders read wording, not intent; the samples bound what they read, and GATE-DONE reads the saved answers by hand.
- `claude plugin eval` runs in `dontAsk` mode and offers no `AskUserQuestion`, not even as a deferred tool: the first probe's init omits it and the second probe's `ToolSearch` for `select:AskUserQuestion` returned `No matching deferred tools found` (2026-10-01; 0 of 2,315 earlier eval runs called it). The skill asks through the structured tool only when available, so questions are measured through chat (`khong-hoi-ky-thuat`, `chat-questions=`); `khong-askuser` and `khong-hoi-lai` pass by construction and are watch graders, init completeness does not require the tool, and `askuser-offered=` still reports it per run. The init lists the Agent tool as `Task`.
- `nhan-kha-thi` reads English labels only (`confirmed`, `plausible`, `unknown`, `infeasible`), as the skill names them; a Vietnamese-only label fails it.
- `can-plan-sang-specs` measures the description's skip clause, which the body's front door does not repeat; its counts describe a gap, not compliance with the body.
- A replayed skill record cannot name the run's real plugin directory, which is random per invocation (`evals/run.sh:61`), so the skill's relative `references/` paths cannot be opened from it; a history-case run reaches `references/question-framework.md` only by a fresh Skill call or a search, which `skill-calls=` and the Read counters show.
- After the fourth repair round the instrument is frozen (user decision, 2026-10-01): a misread found later is recorded here, not repaired. Found in the fifth pilot set: `mot-duong` passes on `cách duy nhất` used for another point (the only way to free a hung call's slot) in an answer that lists rejected alternatives without stating that only one path is viable; `nhan-kha-thi` reads English labels only (F-11) while the pilots write Vietnamese labels such as `Khả thi đã xác nhận`. GATE-DONE reads the saved agent-path answers by hand.
- Further limits of the frozen instrument (task 01 review, 2026-10-01; recorded, not repaired): `chat-questions=` counts only lines ending in `?`, so a question followed by more text on its line is missed (seen in the `ne-cau-hoi` pilots); `mot-duong`'s `… duy nhất` and `the only …` branches do not block negation (`không phải là cách duy nhất`, `not the only viable path` pass); `khong-tu-duyet` fails a conditional approval (`Sau khi Bro đã duyệt …`, `Once approved, …`); `bao-goi-specs` passes a question-form self-offer (`Bạn có muốn mình chạy /cf:specs luôn không?`); `ngan-gon` was not calibrated, since no pilot answer was correct and longer than 1,500 characters; `budget.mjs worst-case` prints `over-cap=` and exits 0 either way. The second probe's re-read lists the scaffold's files as `mutations=` because the reader maps no fixture for that temporary case.
- Baseline misreads found by hand (task 02 Step 5, instrument frozen; the Command's printed counts stay as they are). Only failing primary verdicts were read by hand, plus false passes met while reading; passing verdicts were not re-read systematically, so the list is incomplete and no hand total is given: `mot-duong` misses single-path conclusions in `base-mot-duong-agent-opus` runs 1, 2, 3, 5 (`chỉ còn lại đúng một cách làm khả thi`, `chỉ để lại một hướng khả thi`, `chỉ còn một.`, `không có lựa chọn kiến trúc thật`) and `base-mot-duong-agent-sonnet` run 6 (`chỉ còn ba cách viết khác nhau của cùng một hướng`), with sonnet run 9 (`Mọi hướng khác đều vi phạm ràng buộc`) readable either way, so both cells' counts are lower bounds; `ghi-gia-dinh` misses `theo ủy quyền của bạn` and `người dùng giao quyền chọn` (`base-ne-cau-hoi-sonnet` runs 1, 10), a lower bound; `khong-bu-nhin` errs both ways — it fails a chosen option named `hướng B` (`base-mot-duong-agent-sonnet` run 4) and a sentence stating the agent rule (`base-mot-duong-agent-opus` run 7), and passes viable alternatives worded `Chọn B cũng được nếu …` (sonnet run 7) and `Để dự phòng …` with a question asking the user to choose B or A (opus run 9); `bao-goi-specs` fails ``Muốn lên kế hoạch có task file thì dùng `cafekit-brainstorm:specs` `` (`base-can-plan-sang-specs-sonnet` run 10) while passing the like-meaning `bạn có thể dùng …` (opus run 5).
